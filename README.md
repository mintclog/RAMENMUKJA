# 라멘묵자

메뉴를 중심으로 취향을 찾고 평가하는 반응형 웹앱입니다. 로컬 체험 모드와 운영 연결 코드를 포함합니다. 최신 운영 목표는 Vercel + Supabase 이메일·비밀번호 인증 + Google Maps입니다. 이메일 인증·메뉴 등록·비공개 초안·탈퇴 연결 코드를 포함하며 외부 프로젝트는 아직 연결하지 않았습니다. 명세의 크림색 배경과 토마토 레드를 사용하며, 사진과 구분선을 중심으로 구성합니다. 가게 이름은 기본 UI 폰트를 사용하고 밑줄 없이 색상과 굵기로 링크를 구분합니다.

## 이용 안내 문서와 디자인

- `/terms`: 이용약관, `/privacy`: 개인정보처리방침, `/community`: 리뷰 운영정책. 푸터와 체험 시작 화면에서 접근합니다.
- 문서는 로컬 체험판의 실제 저장·전송 동작을 기준으로 작성했습니다. 운영자 명칭·주소·연락처, 개인정보 보호책임자와 문의 접수 절차는 정식 운영 전에 확정해야 합니다. 외부 이미지·폰트 공급자의 처리 및 국외 이전 여부도 운영 환경에 맞춰 검토해야 합니다.
- 작성 참고: [개인정보 보호법 제30조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1034292763), [개인정보보호위원회 2026년 작성지침 개정 안내](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=&nttId=12021), [약관법 제3조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1021562635). 확인일: 2026-10-16.
- 디자인 참고: [Eater](https://www.eater.com/), [The Infatuation](https://www.theinfatuation.com/all). 사진 중심 편집과 명확한 정보 위계를 참고했으며 로고·콘텐츠·소스는 복제하지 않았습니다.
- 화면 표현은 [디자인 정체성 문서](docs/DESIGN_IDENTITY.md), 실제 구현 상태는 [배포 문서](docs/DEPLOYMENT.md)를 참고합니다.

IA·화면별 권한·팝업 구조와 유저 플로우는 [서비스 기획서 12·13절](docs/PRODUCT_PLAN.md#12-사용자-니즈-중심-정보-구조-ia)에 정리했습니다.

## 실행

Node.js 22 이상이 필요합니다. 추가 패키지 설치는 필요하지 않습니다.

Windows에서는 `시작.bat`를 더블 클릭하면 서버를 시작한 뒤 기본 브라우저를 엽니다. 서버 실행 창을 유지하고, 종료하려면 해당 창에서 `Ctrl+C`를 누릅니다. 이미 라멘묵자 서버가 실행 중이면 새 서버를 만들지 않고 페이지를 엽니다.

터미널에서는 다음 명령으로 실행할 수 있습니다.

```sh
npm run dev
```

브라우저에서 http://127.0.0.1:4173 을 엽니다. 서버는 로컬 컴퓨터의 loopback에만 연결됩니다. 다른 포트는 `PORT` 환경 변수로 지정합니다.

```sh
npm test
npm run check
```

배포 파일 생성은 `node scripts/build.mjs`로 실행합니다. 별도 번들러·추가 패키지·lint 도구는 없습니다.

## 타깃과 사용 흐름

핵심 타깃은 생활권에서 새로운 라멘을 탐색하고 먹은 메뉴를 다시 판단하고 싶은 입문·중급 라멘 애호가입니다. 사용자 인터뷰로 입증된 분류가 아닌 초기 가설입니다. 라멘 찾기·기록하기·먹고 싶은·내 기록을 중심으로 구성하며, `/record`에서 먹은 가게를 검색한 뒤 메뉴를 골라 리뷰를 남깁니다. 자세한 니즈·IA·유저 플로우와 검증 과제는 서비스 기획서 3·12·13절을 참고합니다.

## 현재 실행 상태

로컬 실행은 가상 데이터 기반 체험 모드이며 최신 제품 결정의 실서비스 구현 완료를 뜻하지 않습니다. 현재 기능·운영 제한·과거 검증은 [배포 문서](docs/DEPLOYMENT.md)에서 확인합니다.

## 실서비스 배포

최신 결정은 다음과 같습니다.

- 회원가입: 이메일·비밀번호·닉네임. 닉네임은 자동 생성값을 수정할 수 있고 가입 후에도 변경할 수 있습니다. 이메일 인증·재발송·비밀번호 재설정을 제공합니다. 실명·전화번호는 요구하지 않습니다.
- 가게 등록: 이메일 인증을 마친 회원이 가게 이름·주소·지도 위치를 직접 제출하고, 관리자가 중복·위치를 검토한 뒤 승인한 가게만 공개합니다. 메뉴는 인증 회원이 공개된 가게에 직접 추가하며 관리자 승인 없이 즉시 공개합니다.
- 리뷰 작성: 가게 페이지 → 메뉴 선택(없으면 등록) → 리뷰 작성. 메뉴 선택 카드와 같은 크기의 `+ 메뉴 추가`를 제공합니다. 추가 시 메뉴명·가격·장르·사진이 필수이며 전체 이름·기존 메뉴 중복 금지 안내는 추가 입력창에 표시합니다. 일반 사용자는 메뉴 이름 변경·삭제를 할 수 없습니다.
- 주문 옵션: `#곱빼기`, `#차슈추가`처럼 Enter/추가로 태그를 만들고 삭제할 수 있습니다. 리뷰·비공개 초안에 동일하게 적용하며 별도 메뉴로 만들지 않습니다. 취향·협찬 입력은 제거하고 국물·면·고명은 ‘더 자세히 기록하기’로 펼칩니다.
- 사진: 메뉴 등록 사진을 작성 중 리뷰로 이어받습니다. 대표 사진은 사진이 있는 공개 리뷰 중 좋아요가 가장 많은 리뷰에서 고르고, 사진이 없으면 회색 이미지를 표시합니다.
- 초기 운영: 운영자가 직접 라멘집을 방문하고 서비스를 사용하며 실제 가게·메뉴·리뷰를 확보합니다.
- 재평가: 같은 회원·같은 메뉴는 기존 리뷰를 불러와 수정합니다. 리뷰 수는 늘리지 않고 평균·분포를 갱신하며 작성일·수정일을 구분합니다.
- 지도: Google Maps로 승인 가게 위치를 표시하고 외부 길찾기를 연결합니다. 지도에서 가게를 자동 수집·등록하지 않습니다. 주소 검색·좌표 변환용 추가 API는 별도로 정합니다.

위 내용은 최신 제품 목표이며 구현 완료 선언이 아닙니다. 외부 연결과 최신 요구사항의 구현·검증 상태는 배포 문서에서 관리합니다.

계정 생성·환경 설정·DB 적용·운영자 지정 절차는 [배포 문서](docs/DEPLOYMENT.md)를 따릅니다. 운영 환경에서 연결 설정이 없으면 가상 데이터로 전환하지 않습니다. `ALLOW_PUBLIC_SIGNIN`은 이메일 인증 흐름을 여는 플래그이며 실제 DB·SMTP·운영 정책 검증 후에만 `true`로 엽니다. 기존 로컬 기록을 운영 DB에 자동 전송하지 않습니다.

## 남은 외부 설정과 검증

1. Supabase 프로젝트에 초기 SQL과 추가 마이그레이션을 순서대로 적용하고 실제 RLS·Storage를 검증합니다.
2. Email 인증·운영 SMTP·인증/재설정 메일 템플릿과 운영 URL을 설정합니다.
3. Google Cloud 지도 키·지도 ID·결제·도메인 제한을 설정합니다.
4. 탈퇴용 서버 관리 키를 안전한 런타임 설정에 공급하고 사진 복사·정리와 개인정보 점검 흐름을 실제 계정으로 검증합니다.
5. Vercel 프로젝트 연결과 원격 배포 후 도메인·쿠키·메일 복귀·모바일 지도를 확인합니다.

프로젝트 의존성은 추가하지 않았습니다. GitHub 소스 업로드와 실제 서비스 배포는 별도이며, 이번 변경은 아직 커밋·push하지 않았습니다.

서비스 목적과 범위는 [서비스 기획서](docs/PRODUCT_PLAN.md), 상세 제품 기준은 [구현 명세서](docs/ramenmukja-spec.md), 시각 기준은 [디자인 정체성 문서](docs/DESIGN_IDENTITY.md)를 참고합니다.

## 문서 안내와 구현·검증 기록

기획서는 제품 결정, 명세서는 동작·예외, 디자인 문서는 화면 표현을 담당합니다. 실제 구현 상태와 과거 테스트·빌드·브라우저 검증은 [배포 문서](docs/DEPLOYMENT.md)에 모았습니다. 미등록 가게는 메뉴·리뷰를 비공개 초안으로 보관하고 가게 승인 후 작성자가 발행합니다. 탈퇴 시 개인 저장 목록·불필요한 계정정보는 삭제하고 공용 메뉴는 유지합니다. 공개 리뷰·사진은 탈퇴 전 삭제 선택, 보존 시 식별정보 분리·개인정보 점검을 적용합니다. 두 정책은 확정됐으며 실제 구현 상태는 배포 문서에서 관리합니다.
