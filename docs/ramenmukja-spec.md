# 라멘묵자 웹사이트 구현 규칙 및 명세서

버전: 1.7
작성일: 2026-10-16  
최종 수정·문서 검증일: 2026-10-17  
상태: 이메일 가입·사용자 직접 등록·Google Maps 결정 반영

지금까지 논의한 서비스 방향과 디자인을 반영한다. 인증은 Supabase Auth의 이메일·비밀번호 방식, 지도는 Google Maps를 사용한다. 가게는 사용자의 직접 등록 요청을 관리자가 검토해 공개하며 지도 서비스에서 자동 수집·등록하지 않는다. 초기 대상 지역과 상세 운영 정책은 추가 결정한다. 이 문서는 목표 기준이며 현재 코드의 완료 상태를 뜻하지 않는다.

## 1. 서비스 목적과 핵심 원칙

라멘묵자는 가게보다 메뉴를 중심으로 평가하고, 자신의 취향에 맞는 한 그릇을 찾는 반응형 웹서비스다.

사용자가 해결할 핵심 질문:

- 근처에서 어떤 라멘을 먹을 수 있는가?
- 이 가게에서는 어떤 메뉴를 고르면 좋은가?
- 국물·면·고명의 특징이 내 취향과 맞는가?
- 이 메뉴의 점수를 믿을 만한 근거가 있는가?

구현 원칙:

- 가게명보다 메뉴명과 메뉴 평가를 우선한다.
- 3점도 좋은 평가로 받아들여지도록 안내한다.
- 5점은 ‘내 인생의 한 그릇’이라는 특별한 의미를 갖는다.
- 평균 점수와 평가 수를 항상 함께 보여준다.
- PC와 모바일에서 동일한 핵심 기능을 제공한다.
- 평가 작성 과정은 짧게 유지하고, 세부 항목은 선택적으로 제공한다.

## 2. 초기 구현 범위

| 포함 | 이후 검토 |
|---|---|
| 메뉴 검색·목록·상세 | 개인화 추천 알고리즘 |
| 가게 상세와 판매 메뉴 | 팔로우·댓글·커뮤니티 |
| 지역·장르 필터 | 영수증 인증 |
| 메뉴별 리뷰 작성·수정·삭제 | 방문 횟수·방문 기록 관리 |
| 별점 분포·세부 평가 | 리뷰어 등급과 점수 보정 |
| 메뉴 저장 | 배달·예약·결제 |
| 로그인·내 기록 | 유료 기능·광고 상품 |
| 위치 기반 탐색·지도 연결 | 전국 데이터 자동 수집 |
| 신고·등록 요청·관리자 처리 | 복잡한 랭킹 시스템 |

초기 운영자는 직접 라멘집을 방문하고 서비스를 사용하며 실제 가게·메뉴·리뷰를 확보한다. 구체적인 시작 지역은 별도 선택한다. 전국 단위의 완전한 목록이나 지도 서비스의 자동 수집을 전제로 구현하지 않는다. 운영자는 가게 요청을 검토하고 승인된 가게 정보를 등록한다. 공개된 가게의 메뉴는 인증 회원이 직접 추가하고 관리자 승인 없이 즉시 공개한다. 미등록 가게의 메뉴·리뷰는 비공개 초안으로 보관한다.

‘내 인생 라멘’ 한 메뉴를 별도로 선정하는 기능은 추후 검토하며, 초기 별점 체계에는 포함하지 않는다.

## 3. 디자인 방향

### 3.1 컨셉

‘먹음직스럽고 따뜻한 라멘 메뉴판 + 정돈된 미식 수첩’을 지향한다.

음식 사진이 시선을 끌고, 메뉴와 평가 정보는 차분하게 읽히도록 구성한다. 일본풍 장식은 작은 요소에 한정하고, 한글 가독성과 탐색 편의성을 우선한다.

식욕을 돋우는 분위기는 따뜻한 컬러와 음식 사진·조명·배치가 함께 만든다. 전체 화면을 강한 빨간색으로 채우지 않는다.

### 3.2 컬러

| 디자인 토큰 | 값 | 용도 |
|---|---|---|
| `color-primary` | `#C9432B` | 로고, 주요 버튼, 선택 상태 |
| `color-background` | `#FFF8EE` | 전체 배경 |
| `color-surface` | `#FFFFFF` | 카드, 입력 영역 |
| `color-text` | `#30241F` | 제목, 본문, 점수 |
| `color-text-muted` | `#75665D` | 주소, 날짜, 보조 설명 |
| `color-accent` | `#F2B544` | 작은 배지, 장식 |
| `color-border` | `#EADFD2` | 경계선 |
| `color-error` | `#B42318` | 입력 오류 |

- 크림색을 넓은 배경에, 레드를 주요 행동과 선택 상태에 사용한다.
- 노른자색은 작은 장식과 배지에 한정한다.
- 별점 숫자는 짙은 브라운으로 읽기 쉽게 표현한다.
- 노른자색 위에 흰색 본문을 배치하지 않는다.
- 실제 화면에서 대비를 확인하고 필요하면 토큰 값을 조정한다.

### 3.3 타이포그래피와 형태

- 기본 폰트: `Pretendard`, 시스템 sans-serif 대체 폰트 지정
- 본문: `16px`, 줄 간격 약 `1.6`
- 보조 정보: `14px` 권장
- 메뉴 제목: `18–20px`
- 페이지 제목: 모바일 `28px`, PC `36px`
- 평점과 비교용 숫자는 가능한 경우 일정한 숫자 폭 사용
- 간격 체계: `4 / 8 / 12 / 16 / 24 / 32 / 48px`
- 카드 모서리: 약 `12px`
- 버튼 모서리: 약 `8px`
- 음식 사진은 목록에서 일정한 비율로 통일하고 상세에서 원본 확인 제공

로고는 두께감 있고 잘 읽히는 한글을 중심으로 한다. 그릇이나 면 한 가닥을 작은 요소로 사용할 수 있다. 과도한 붓글씨·일본어 장식은 피한다.

## 4. 화면 구조와 주소

| 화면 | 권장 경로 | 핵심 기능 |
|---|---|---|
| 홈 | `/` | 검색, 장르 탐색, 근처 메뉴, 최근 리뷰 |
| 탐색 | `/explore` | 검색 결과, 필터, 정렬, 목록·지도 |
| 메뉴 상세 | `/menus/:menuId` | 메뉴 정보, 점수, 분포, 리뷰 |
| 가게 상세 | `/shops/:shopId` | 위치, 가게 정보, 판매 메뉴 |
| 리뷰 작성·수정 | `/menus/:menuId/review` | 메뉴 평가 |
| 저장 목록 | `/saved` | 저장한 메뉴 |
| 내 기록 | `/me` | 작성 리뷰, 별점 분포 |
| 로그인 | `/login` | 이메일·비밀번호 로그인, 회원가입·비밀번호 재설정 진입 |
| 관리 | `/admin` | 등록 요청, 중복, 신고·보존 리뷰 개인정보 점검 |
| 이용약관 / 개인정보 / 리뷰 정책 | `/terms` / `/privacy` / `/community` | 이용 정책 열람 |

경로는 기존 프로젝트 구조가 있다면 그 구조에 맞춘다.

회원가입은 `/login?mode=signup`, 인증 메일 확인은 `/login?mode=verify`, 재발송은 `/login?mode=resend`, 재설정 메일 요청은 `/login?mode=recover`, 새 비밀번호 입력은 `/login?mode=reset`을 사용한다. 인증 링크는 자동 소비하지 않고 확인 버튼으로 제출한다. 닉네임 변경·탈퇴는 `/me`, 가게 요청의 비공개 초안은 `/me?draft=:requestId`에서 제공한다. 회원가입 화면에는 이메일·비밀번호·닉네임을 제공한다. 닉네임은 처음에 자동 생성한 값으로 채우고 가입 시 또는 가입 후 사용자가 수정할 수 있게 한다. 실명·전화번호는 요구하지 않으며 공개 작성자명에는 이메일 대신 닉네임을 사용한다. 약관 확인과 가입 연령 확인은 별도로 제공한다.

## 5. 화면별 구성

### 5.1 홈

다음 순서로 배치한다.

1. 로고와 내비게이션
2. ‘오늘은 어떤 한 그릇?’ 문구와 검색창
3. `내 근처`, `돈코츠`, `시오`, `쇼유`, `탄탄면`, `아부라소바`, `츠케멘`
4. 근처 또는 선택 지역의 메뉴
5. 장르·육수별 탐색
6. 최근 작성된 리뷰

긴 홍보 배너나 자동 재생 슬라이드로 탐색을 밀어내지 않는다. 사용자가 ‘내 근처’를 선택하는 등 위치 기반 기능을 실행할 때 위치 권한을 요청하고, 수동 지역 선택도 제공한다.

### 5.2 탐색

- 가게명·메뉴명·지역으로 검색한다.
- 지역·메뉴 장르 필터를 제공한다.
- 위치가 있을 때만 거리순을 제공한다.
- 정렬은 검색 관련도, 평가 많은 순, 평점순, 거리순을 제공한다.
- 평점순은 평가 수 조건을 함께 제공한다.
- 평점순에서는 초기 기본값으로 `평가 5개 이상`을 적용한다. 결과가 없으면 ‘평가 수 조건을 해제하고 보기’를 표시하고 해당 조건만 해제해 다른 검색·지역·장르 조건은 유지한다.
- 검색어·필터·정렬·선택 지역을 URL에 반영해 새로고침과 공유를 지원한다.

지도에는 가게 위치를 표시한다. 핀 선택 시 해당 가게의 메뉴를 확인할 수 있게 하며, 같은 가게의 메뉴마다 핀을 중복 표시하지 않는다.

### 5.3 메뉴 카드

정보 우선순위:

1. 메뉴 사진
2. 메뉴명
3. 가게명·지역 또는 거리
4. 평균 점수·평가 수
5. 장르 태그
6. 가격·저장 버튼

메뉴명이 가게명보다 먼저 보여야 한다. 메뉴 링크와 저장 버튼은 각각 독립적으로 작동한다. 예시 데이터에서도 3점대 메뉴가 자연스럽게 등장하도록 구성한다.

### 5.4 메뉴 상세

- 사진
- 메뉴명·가게 링크·가격·판매 상태
- 장르와 국물·면·고명 평가
- 전체 평균·평가 수·별점 분포
- 국물·면·고명 세부 평가
- 리뷰 작성 진입은 해당 가게 페이지의 메뉴 선택으로 연결한다. 기존 메뉴를 미리 선택할 수 있게 하되 다른 메뉴와 추가 카드를 함께 보여준다. 해당 메뉴에 본인 리뷰가 있으면 `내 리뷰 수정`으로 표시하고 기존 내용을 불러온다.
- 리뷰 목록

세부 평가에는 해당 항목의 응답 수를 표시한다. 리뷰 사진은 크게 열어 확인할 수 있게 한다.

### 5.5 가게 상세

- 가게명·주소·위치
- 외부 지도에서 보기·길찾기
- 제공되는 경우 영업시간과 정보 출처
- 판매 중인 메뉴와 메뉴별 평가
- 판매 종료 메뉴를 별도로 확인하는 기능

가게 종합점수보다 메뉴별 평가를 우선 배치한다.

## 6. 별점과 집계 규칙

### 6.1 별점의 의미

사용자 입력은 초기 버전에서 1~5점 정수로 제공한다.

| 점수 | 선택 시 표시할 설명 |
|---|---|
| 1 | 크게 아쉬웠어요 |
| 2 | 아쉬운 부분이 있었어요 |
| 3 | 맛있게 먹었어요. 좋은 라멘입니다 |
| 4 | 멀리서 찾아가서라도 다시 먹고 싶어요 |
| 5 | 지금까지 먹은 라멘 중 손에 꼽는, 내 인생의 한 그릇입니다 |

- 초기 선택값은 비워 둔다.
- 선택한 점수의 설명을 즉시 표시한다.
- 5점 선택 시 특별했던 이유를 필수로 입력받는다.
- 주간·월간 5점 횟수 제한은 두지 않는다.
- 5점 선택에 축하 효과나 보상 애니메이션을 제공하지 않는다.
- 높은 별점 작성을 유도하는 보상을 제공하지 않는다.
- 평균·평가 수·점수 분포를 함께 보여준다.

### 6.2 메뉴 점수

- 사용자 한 명은 메뉴 하나에 유효한 리뷰 하나를 갖는다.
- 재평가하면 기존 리뷰를 수정한다.
- 메뉴 점수는 공개 상태인 유효 리뷰의 전체 별점 평균이다.
- 국물·면·고명 점수로 전체 별점을 자동 계산하지 않는다.
- 세부 평가는 해당 항목에 응답한 리뷰만 평균에 포함한다.
- 삭제·숨김 리뷰는 모든 집계에서 제외한다.
- 평균은 원래 값으로 계산하고 화면에서 소수 첫째 자리까지 표시한다.
- 리뷰가 없으면 `0.0` 대신 `아직 평가가 없어요`를 표시한다.
- 평가 5개 미만에는 `평가가 적어요` 안내를 표시한다.
- 사용자별 비공개 가중치나 임의의 점수 보정은 적용하지 않는다.

### 6.3 가게 종합점수

가게 종합점수를 제공할 경우 판매 중인 메뉴에 연결된 공개 리뷰의 전체 별점 평균으로 계산한다. 메뉴별 평균을 다시 단순 평균하지 않는다.

점수 이름은 `판매 중인 메뉴 종합`으로 표시하고 계산 범위를 안내한다. 판매 종료 메뉴의 리뷰는 해당 메뉴 상세에 남기되 이 종합점수에서는 제외한다.

## 7. 리뷰 작성 규칙

리뷰 작성은 가게 페이지 → 해당 가게의 메뉴 선택(없으면 메뉴 등록) → 리뷰 작성 순서다. 본인이나 다른 사용자가 등록한 기존 메뉴를 보여주고 같은 크기의 `+ 메뉴 추가` 카드 또는 버튼을 옆에 배치한다. 메뉴 추가 화면에서만 “메뉴판에 적힌 전체 이름을 입력해주세요”와 “이미 등록된 메뉴는 추가하지 말고 기존 메뉴를 선택해주세요”를 안내한다.

메뉴 등록에는 메뉴명·가격·장르·사진이 필수다. 공개된 가게에 추가한 메뉴는 관리자 승인 없이 즉시 공개하고 선택 상태로 리뷰 작성을 이어간다. 미등록 가게의 메뉴는 13절의 비공개 초안 예외를 따른다. 일반 사용자는 본인이 등록한 메뉴라도 이름을 변경하거나 삭제할 수 없다. 잘못된 정보는 운영자가 수정·정리한다. 특제·곱빼기·추가 토핑은 별도 메뉴로 나누지 않고 리뷰의 주문 옵션으로 표기한다.

메뉴 등록 사진은 별도 홍보 이미지가 아니라 작성 중인 리뷰에 이어지는 사진이다. 같은 파일을 다시 올리지 않도록 리뷰 사진 목록으로 넘긴다. 기존 메뉴 리뷰의 사진은 선택이며, 새 메뉴를 등록할 때만 사진 입력이 필수다. 메뉴 대표 사진은 사진이 있는 공개·유효 리뷰 중 좋아요가 가장 많은 리뷰의 사진을 사용한다. 리뷰가 하나면 그 리뷰의 사진을 사용하고 공개 리뷰 사진이 없으면 회색 임시 이미지를 표시한다. 메뉴만 추가한 뒤 리뷰 작성을 중단하면 미발행 초안 사진을 대표 사진으로 공개하지 않는다.

인증 회원은 본인 리뷰를 제외한 리뷰에 한 번 좋아요를 누르거나 취소할 수 있다. 대표 사진은 좋아요 수가 같으면 먼저 작성된 리뷰를 우선하고, 그 리뷰의 첫 사진을 사용한다. 중복 메뉴 경고는 예방 안내이며 모든 중복을 막는다는 보장은 아니다. 중복 메뉴 통합 시 한 회원의 리뷰가 겹치는 처리 기준도 미정으로 유지한다.

같은 회원이 같은 가게의 같은 메뉴를 다시 평가하면 새 리뷰를 쌓지 않고 기존 리뷰를 수정한다. 기존 리뷰가 있으면 `내 리뷰 수정`으로 안내하고 별점·본문·사진·선택 평가·주문 옵션을 불러온다. 수정 시 리뷰 수는 늘리지 않고 평균·분포를 갱신하며 작성일과 수정일을 구분해 표시한다.


| 항목 | 필수 여부 | 규칙 |
|---|---|---|
| 메뉴 | 필수 | 해당 가게의 기존 메뉴 선택 또는 작성 중 추가. 메뉴 상세 진입 시 자동 선택 |
| 전체 별점 | 필수 | 1~5점 |
| 리뷰 본문 | 조건부 | 5점 선택 시 필수 |
| 국물·면·고명 점수 | 선택 | 해당 없는 항목은 생략 |
| 리뷰 사진 | 조건부 | 기존 메뉴 리뷰는 선택, 새 메뉴 등록 시 필수 사진을 리뷰로 이어받음. 최대 5장 기준 |
| 주문 옵션 | 선택 | `#곱빼기`, `#차슈추가` 등 사용자 입력 태그. 별도 메뉴로 생성하지 않음 |

- 메뉴 선택과 기본 평가를 먼저 표시한다. 국물·면·고명은 기본 접힌 ‘더 자세히 기록하기’에서 입력한다. 진하기·짠맛·면 식감과 협찬 여부 입력 필드는 제공하지 않는다.
- 아부라소바 등 메뉴 유형에 맞지 않는 평가 항목은 표시하지 않는다.
- 기본 고명과 추가 토핑이 혼동되지 않도록 안내한다.

주문 옵션은 리뷰와 비공개 초안에서 동일한 태그 입력을 제공한다. Enter 또는 ‘추가’로 확정하고 각 태그의 삭제 버튼으로 제거한다. `#` 없이 입력해도 앞에 붙여 표시하며 입력한 이름과 내부 공백은 유지한다. `#`·쉼표·줄바꿈은 여러 태그의 구분자로 사용하고 완전히 같은 이름의 중복은 한 번만 추가한다. 한글 조합 중 Enter는 태그 확정이나 폼 제출로 처리하지 않는다. 저장 시 아직 확정하지 않은 입력도 포함한다. 저장 문자열은 `#곱빼기 #차슈추가` 형태로 전체 300자 이내이며 초과하면 입력을 유지하고 오류를 표시한다. 기존 쉼표 구분 자유 입력도 태그로 불러오고, 저장·새로고침·수정·초안 비교·공개 리뷰에서 같은 이름으로 표시한다.

- 저장 실패 시 작성 내용이 사라지지 않아야 한다.
- 전송 중에는 중복 제출을 막는다.
- 수정·삭제 후 평균과 분포를 갱신한다.
- 사진 업로드 시 위치 등 불필요한 메타데이터를 제거한다.

## 8. 태그와 데이터 관리

검색·분류용 태그는 메뉴에 먼저 연결한다. 가게에는 판매 메뉴의 분류 태그를 모아 표시한다. 리뷰의 주문 옵션 태그는 해당 리뷰에만 연결하며 메뉴 분류나 검색 필터에 자동으로 추가하지 않는다.

| 구분 | 예시 |
|---|---|
| 육수 | 돼지, 닭, 해산물, 혼합 |
| 간 | 시오, 쇼유, 미소 |
| 형태·스타일 | 국물 라멘, 츠케멘, 아부라소바, 탄탄면 |
| 사용자용 탐색 태그 | 돈코츠, 시오, 쇼유 등 익숙한 명칭 |

실제 메뉴의 중복 분류와 복수 선택을 허용한다. 모든 세부 태그를 필수로 요구하지는 않지만 메뉴 등록의 장르는 필수다.

주요 데이터 관계:

- 가게는 여러 메뉴를 갖는다.
- 메뉴는 하나의 가게에 속한다.
- 리뷰는 사용자와 메뉴에 연결된다.
- 저장은 사용자와 메뉴에 연결된다.
- 신고는 리뷰와 연결된다.
- 메뉴에는 판매 중·판매 종료 상태를 둔다.

가격 변경으로 기존 리뷰가 삭제되면 안 된다. 특제·곱빼기·추가 토핑만 다른 경우에는 새 메뉴로 추가하지 않고 리뷰에 표기한다. 그 외 별개의 메뉴 등록에도 관리자 사전 승인을 요구하지 않는다. 중복·잘못된 메뉴 정보는 공개 후 관리하며, 과거 리뷰를 자동으로 합치지 않는다.

## 9. 반응형 규칙

| 구간 | 기준 | 구성 |
|---|---|---|
| 모바일 | `0–767px` | 1열 중심, 하단 내비게이션 |
| 태블릿 | `768–1023px` | 2열 목록, 공간에 따라 지도 전환 |
| PC | `1024px` 이상 | 3열 목록 또는 목록·지도 병렬 |

- 기본 콘텐츠 최대 폭은 약 `1200px`로 한다.
- 모바일 좌우 여백은 `16px` 이상으로 한다.
- `320px` 폭에서도 본문 가로 스크롤 없이 사용할 수 있어야 한다.
- 모바일 하단 내비게이션은 `탐색 / 저장 / 내 기록`으로 구성한다.
- 모바일 필터는 하단 패널로 표시한다.
- PC 지도 검색은 목록과 지도를 병렬 배치한다.
- 모바일에서는 목록·지도 전환을 제공한다.
- 고정 버튼과 하단 메뉴는 기기 안전 영역과 키보드를 고려한다.
- 리뷰 본문과 상세 정보는 PC에서도 지나치게 긴 줄이 되지 않도록 제한한다.

## 10. 상호작용과 접근성

- 호버는 테두리·배경·그림자의 작은 변화로 표현한다.
- 버튼과 링크는 클릭 가능한 상태가 명확해야 한다. 텍스트 옆 장식용 오른쪽 화살표 `→`는 사용하지 않고 검색 제출은 돋보기 아이콘으로 표시한다.
- 전환 효과는 약 `150–200ms`를 기본으로 한다.
- 저장 성공·실패는 짧은 안내와 상태 변화로 알린다. 카드와 상세 화면 모두 미저장은 윤곽 책갈피, 저장은 기본 레드로 채운 책갈피로 표시하고 `aria-pressed`를 동기화한다. 상세 문구는 ‘저장’/‘저장됨’으로 전환하고 취소하면 원래 상태로 되돌린다.
- 호버 없이도 모든 기능을 사용할 수 있어야 한다.
- PC 별점 호버는 미리 보기이며 클릭해야 확정된다. 모바일은 탭으로 선택한다.
- 키보드 탐색과 명확한 포커스 표시를 제공한다.
- 별점은 키보드로 선택 가능하고 점수 설명을 읽을 수 있어야 한다.
- 색만으로 선택·오류·점수를 구분하지 않는다.
- 주요 터치 영역은 최소 `44 × 44px`를 확보한다.
- 모션 감소 설정을 존중한다.
- 일반 본문 대비는 `4.5:1` 이상을 목표로 검증한다.

## 11. 로그인과 권한 및 운영

- 메뉴·가게·리뷰 열람은 비회원도 가능하다.
- 리뷰 작성·저장·신고는 로그인해야 가능하다.
- Supabase Auth로 이메일·비밀번호 회원가입과 로그인을 제공한다. 소셜 로그인은 초기 범위에서 제외한다.
- 이메일 인증을 완료한 계정만 리뷰 작성·저장·신고·등록 요청을 할 수 있다.
- 가입 확인 메일 재발송과 비밀번호 재설정을 제공한다. 운영용 이메일 발송 서비스를 설정하고 재발송·로그인 시도 남용을 방지한다.
- 비밀번호 저장·검증은 Supabase Auth에 맡기며 앱 DB·로그·문서에 비밀번호를 보관하지 않는다.
- 로그인 후 원래 화면이나 작성 흐름으로 복귀한다.
- 사용자는 본인 리뷰만 수정·삭제할 수 있다. 일반 사용자의 공용 메뉴 이름 변경·삭제는 서버에서도 차단한다.
- 닉네임은 가입 화면에서 자동 생성한 값을 편집할 수 있고 가입 후에도 변경할 수 있다. 공개 리뷰에는 이메일을 표시하지 않는다.
- 관리자 권한은 서버에서 검증한다.
- 이메일 인증을 마친 사용자의 가게 등록은 요청으로 접수한다. 가게 요청만으로 공개 목록에 즉시 등록하지 않는다.
- 이메일 인증을 마친 사용자는 공개된 가게에 메뉴를 직접 추가한다. 공개된 가게의 메뉴와 발행한 리뷰는 관리자 사전 승인 없이 공개한다. 미등록 가게에서는 비공개 초안만 작성하고 가게 승인 후 작성자가 발행한다. 메뉴·리뷰 자체의 별도 승인 절차는 두지 않는다.
- 가게명·주소·지도 위치를 입력받고 중복 여부와 실제 위치를 검토한 뒤 관리자가 승인·반영한다. 메뉴는 가게와 별도로 연결한다.
- 요청 상태는 접수·검토 결과를 이용자가 구분할 수 있게 안내한다. 중복 가게에 연결하거나 보완이 필요한 경우 사유를 안내한다.
- 관리자는 등록 요청·중복 항목·신고를 처리한다.
- 신고만으로 리뷰를 자동 삭제하지 않는다.

## 12. 지도와 외부 데이터

지도 공급자는 Google Maps로 확정한다. 지도는 직접 등록해 승인된 가게의 위치 표시·핀 선택과 외부 길찾기에 사용한다. Google Maps·Places에서 가게 목록을 자동 수집하거나 자동 등록하지 않는다.

- 자체 리뷰·메뉴 데이터와 외부 장소 데이터를 구분한다.
- 주소와 지도 위치는 사용자가 직접 입력·확인한다. Google의 주소 검색·Geocoding·Places 같은 추가 API 사용 여부는 필요한 UX와 비용·이용 조건을 검토한 뒤 별도 결정한다.
- 사이트 내부 지도에는 Google Cloud 프로젝트·결제 설정·사용 API에 맞는 키 제한과 사용량 관리가 필요하다. 브라우저용 지도 키와 서버 비밀 키를 구분한다.
- 외부 데이터는 공급자의 저장·표시·출처 정책을 확인한 범위에서 사용한다.
- 지도 연동 전에도 자체 등록 가게와 지역 선택으로 탐색할 수 있어야 한다.
- 위치 권한 거부 시 수동 지역 선택으로 계속 사용할 수 있다.
- 지도 로딩 실패 시 목록·주소·외부 지도 링크를 제공한다.
- 실제 위치가 없으면 거리를 임의로 표시하지 않는다.
- 서버용 비밀 키는 클라이언트에 포함하지 않는다.

## 13. 필수 예외 화면

미등록 가게의 비공개 초안과 탈퇴 후 콘텐츠 처리는 확정 정책이다.

### 13.1 미등록 가게 초안

가게 검색 → 없으면 등록 요청 → 메뉴·리뷰 비공개 초안 작성 → 가게 승인 후 작성자가 초안으로 돌아와 발행한다. 가게 승인만으로 메뉴·리뷰를 자동 발행하지 않는다. 승인 전 초안 메뉴·리뷰·사진은 작성자와 검토 권한이 있는 운영자만 접근하며 공개 목록·지도·점수·대표 사진에서 제외한다. 중복 가게로 연결하거나 반려되는 경우 내용을 보존하고 다음 행동을 안내한다. 가게 승인 후에도 초안은 작성자가 발행할 때까지 비공개다. 중복 연결 대상 메뉴에 본인 리뷰가 이미 있으면 새 공개 리뷰를 만들지 않고 기존 리뷰 수정 규칙을 적용하며 내용을 자동 덮어쓰지 않는다. 보관기간·알림 등 상세 운영 기준은 기획서의 추가 결정 항목을 따른다.

### 13.2 탈퇴와 콘텐츠

탈퇴 시 개인 저장 목록과 불필요한 계정정보를 삭제하고 사용자가 추가한 공용 메뉴는 유지한다. 공개 리뷰·사진은 탈퇴 전에 삭제 여부를 선택할 수 있게 하고, 보존을 선택한 자료는 작성자 식별정보를 분리하며 본문·사진 등의 개인정보를 점검한 후 보존 여부를 결정한다. 닉네임만 바꾸는 처리를 익명화 완료로 간주하지 않는다. 모든 자료를 무기한 보존하는 정책은 적용하지 않는다. 보관기간·삭제 요청 창구·콘텐츠 이용 범위의 상세 운영 기준은 별도로 정한다. 탈퇴 전 삭제 대상과 보존 가능 대상을 확인하고 선택 결과를 안내한다. 보존된 콘텐츠는 기존 이메일·닉네임 등 계정 식별정보를 공개하지 않으며 작성자 표시는 ‘탈퇴한 회원’으로 통일한다. 삭제·숨김 처리된 리뷰와 사진은 점수와 대표 사진 후보에서 제외한다. 탈퇴 처리 성공 여부는 서버 결과로 확인하고 실패를 완료로 안내하지 않는다.

### 13.3 공통 예외 상태

다음 상태를 각 화면에 구현한다.

- 초기 로딩
- 검색 결과 없음
- 평가 없음
- 사진 없음
- 판매 종료
- 위치 권한 거부
- 지도 또는 네트워크 오류
- 로그인 만료
- 리뷰 제출 실패
- 접근 권한 없음
- 존재하지 않는 메뉴·가게

공개 리뷰 사진이 없으면 회색 임시 이미지를 사용한다. 대표 사진 후보에서 숨김·삭제·미발행 리뷰와 사진을 제외하고 좋아요·공개 상태가 바뀌면 다시 선정한다. 동률이면 먼저 작성된 리뷰, 그 리뷰의 첫 사진을 사용한다. 오류 화면에는 재시도나 다른 탐색 경로를 제공한다.

## 14. 개발 규칙과 완료 조건

### 14.1 개발 규칙

- 기존 프로젝트의 기술 스택·스타일·구조를 먼저 확인한다.
- 필요한 최소 변경으로 구현하고 불필요한 의존성은 추가하지 않는다.
- 공통 버튼·카드·별점 입력·태그·필터를 재사용하되 불필요한 추상화는 피한다.
- 샘플 데이터는 실제 서비스 데이터와 구분한다.
- 연결되지 않은 기능을 성공한 것처럼 표시하지 않는다.
- 비밀 정보나 인증 정보를 소스와 문서에 기록하지 않는다.
- 실제 실행한 test·build·lint만 결과로 보고한다.

### 14.2 완료 조건

- [ ] PC·모바일에서 탐색 → 가게 페이지 → 로그인 → 메뉴 선택(없으면 등록) → 리뷰 작성 흐름이 동작한다.
- [ ] 이메일 가입·인증·인증 메일 재발송·비밀번호 재설정·로그아웃 흐름을 확인한다.
- [ ] 사용자 가게 등록 요청 → 중복·위치 검토 → 승인·공개 흐름을 확인한다.
- [ ] Google Maps에 승인된 가게만 표시하고 핀과 외부 길찾기를 확인한다.
- [ ] 공개된 가게의 기존 메뉴 선택 → 메뉴 추가 → 즉시 공개·선택 유지 → 리뷰 작성 흐름을 확인한다. 전체 이름 안내는 메뉴 추가 입력창에만 표시한다.
- [ ] 같은 회원·같은 메뉴 재평가는 기존 리뷰를 불러와 수정하고 리뷰 수를 늘리지 않으며 평균·분포·수정일을 갱신한다.
- [ ] 저장·리뷰 수정·삭제가 실제로 반영된다.
- [ ] 리뷰 변경 후 점수·평가 수·분포가 일치한다.
- [ ] 평가가 적거나 없는 메뉴를 정확히 표시한다.
- [ ] 5점 선택 시 기준과 이유 입력란이 표시된다.
- [ ] 비회원과 타인의 리뷰에 대한 권한 검사가 동작한다.
- [ ] 위치 권한 없이도 탐색할 수 있다.
- [ ] 로딩·오류·빈 화면을 확인할 수 있다.
- [ ] 키보드 탐색과 모바일 터치 조작이 가능하다.
- [ ] 메뉴명·가격·장르·사진 필수 입력과 중복 메뉴 안내, 특제·곱빼기·추가 토핑의 리뷰 표기를 확인한다.
- [ ] 자동 생성 닉네임·가입 중/후 변경, 일반 사용자의 메뉴 이름 변경·삭제 차단을 확인한다.
- [ ] 취향·협찬 입력 없이 국물·면·고명 펼치기와 사진 이어받기를 확인한다.
- [ ] 좋아요 기반 대표 사진·리뷰 한 개·사진 없음·후보 숨김/삭제 상태를 확인한다.
- [ ] 결과 없음에서 평가 수 조건만 해제되는지 확인한다.
- [ ] 미등록 가게 초안의 접근 권한·공개 제외·승인 후 수동 발행·중복/반려 시 내용 보존을 확인한다.
- [ ] 탈퇴 전 콘텐츠 삭제 선택, 개인 저장 목록·불필요한 계정정보 삭제, 공용 메뉴 유지, 보존 콘텐츠 식별정보 분리와 개인정보 점검·대표 사진 재선정을 확인한다.
- [ ] 실행한 test·build·lint 결과와 남은 제한사항을 배포 문서에 기록한다.
