## 2. 제품 정의

### 2.1 서비스명과 설명

**라멘묵자 / RAMENMUKJA — 취향으로 찾는 한 그릇**

가게 전체의 평판에 더해, 실제로 고를 메뉴와 그 메뉴를 먹은 경험을 중심으로 탐색한다.

### 2.2 서비스 형태

PC와 모바일에서 같은 핵심 기능을 제공하는 반응형 웹서비스다. 운영 구성은 Vercel + Supabase이며, 이메일·비밀번호 인증과 Google Maps를 사용한다. 구현 상태와 실행 검증 기록은 [배포 문서](DEPLOYMENT.md)에서 관리한다.

### 2.3 핵심 사용자 프로세스

1. 식사 전에는 지역·장르·육수로 메뉴를 비교하고 방문하거나 먹고 싶은 목록에 저장한다.
2. 식사 후에는 기록하기에서 먹은 가게를 찾고 메뉴를 골라 별점과 경험을 남긴다.
3. 내 기록에서 이전 평가·주문 옵션과 비공개 초안을 다시 확인하고 필요하면 수정·발행한다.

```text
식사 전: 라멘 찾기 → 메뉴 비교 → 방문 또는 먹고 싶은 목록
식사 후: 기록하기 → 가게 찾기 → 메뉴 선택 → 리뷰 작성·수정
다시 접속: 먹고 싶은 / 내 기록 → 후보 재확인·초안 이어쓰기
```

### 2.4 확정한 가입·등록·지도 방식

| 항목 | 결정 |
|---|---|
| 가입 | 이메일·비밀번호, 자동 생성 후 수정 가능한 닉네임. Supabase Auth 사용 |
| 인증 보조 흐름 | 이메일 인증·인증 메일 재발송·비밀번호 재설정 |
| 가게 등록 | 로그인한 사용자 직접 등록 요청 → 중복·위치 확인 → 관리자 검토·공개 |
| 메뉴 추가 | 가게 페이지에서 선택 또는 등록. 메뉴명·가격·장르·사진 필수. 공개 가게에서는 즉시 공개, 미등록 가게에서는 비공개 초안. 일반 사용자의 이름 변경·삭제 금지 |
| 재평가 | 같은 회원·같은 메뉴의 기존 리뷰 수정, 리뷰 수 유지·평균/분포 갱신 |
| 지도 | Google Maps에 승인된 가게 표시, 외부 길찾기 연결 |
| 자동 등록 | 지도 서비스에서 가게를 자동 수집·등록하지 않음 |

회원가입 화면에는 이메일·비밀번호·닉네임을 제공한다. 닉네임은 처음에 자동 생성한 값으로 채우고 가입 시 또는 가입 후 사용자가 수정할 수 있게 한다. 실명·전화번호는 요구하지 않으며 공개 작성자명에는 이메일 대신 닉네임을 사용한다. 약관·가입 연령 확인은 별도로 제공한다. 소셜 로그인은 초기 범위에서 제외한다.

### 2.5 초기 범위 밖의 기능

주문·배달·예약·결제, 팔로우·댓글, 영수증 인증, 유료 기능·광고 상품, 전국 자동 수집은 초기 범위에 포함하지 않는다. 개인화 추천과 별도의 ‘내 인생 라멘’ 한 메뉴 선정도 추후 검토 대상이다.

## 3. 문제 정의와 제품 가설

### 3.1 해결할 질문

- 근처에서 어떤 라멘을 먹을 수 있는가?
- 이 가게에서는 어떤 메뉴를 고르면 좋은가?
- 국물·면·고명의 특징이 내 취향과 맞는가?
- 이 점수는 몇 명의 어떤 경험에 근거하는가?

### 3.2 핵심 타깃과 선택 이유

**핵심 타깃: 한국의 도시 생활권에서 라멘집을 반복적으로 방문하며, 다음에 먹을 메뉴와 이전에 먹은 메뉴를 비교하고 싶은 입문·중급 라멘 애호가.** 혼자 또는 소규모로 식사하고 이동 중 휴대전화로 찾거나 식사 직후 기록하는 상황을 우선한다. 도시 생활권은 서비스 이용 맥락이며 첫 운영 지역을 서울·특정 동네로 확정한 뜻은 아니다.

| 구분 | 사용자·상황 | 우선 해결할 필요 |
|---|---|---|
| 1차: 반복 탐색·기록자 | 장르를 조금 알고 새 가게와 다른 메뉴를 시도하는 사람 | 생활권·장르로 후보 찾기, 메뉴별 가격·평가 근거 비교, 먹고 싶은 메뉴 보관, 이전 평가·주문 옵션 재확인 |
| 2차: 라멘 입문자 | 라멘은 먹고 싶지만 장르명과 메뉴 선택이 어려운 사람 | 육수·국물 유무 등 이해하기 쉬운 탐색, 평가 수·사진·가격을 함께 보고 선택 |
| 초기 콘텐츠 참여자 | 직접 방문하는 운영자와 초기 회원 | 검색에서 없는 가게 확인, 메뉴 중복 예방, 짧은 리뷰 작성, 승인 전 기록 보존 |
| 초기 우선 대상 아님 | 예약·배달·결제, 상권 분석, 전국 실시간 영업정보를 원하는 사람 | 해당 기능과 데이터 완전성을 약속하지 않음 |

연령·성별·직업·소득으로 이용을 제한하지 않는다. 가입 연령 조건은 기존 정책을 유지한다. 특정 연령층의 시장 규모나 방문 빈도·전환율을 입증된 수치로 제시하지 않는다. 위 타깃은 창업자의 직접 방문 운영 방식과 메뉴 단위 기록의 반복 사용 가능성에 근거해 이번에 채택한 **초기 포지셔닝 가설**이며 사용자 인터뷰 결과가 아니다.

### 3.3 니즈와 제품 판단

| 사용자가 하려는 일 | 방해 요인 | 설계 결정 | 확인할 사용성 과제 |
|---|---|---|---|
| 오늘 먹을 라멘 고르기 | 가게 점수만으로 어떤 메뉴를 주문할지 모름 | 메뉴명·가격·장르·평가 수를 먼저 비교하고 가게 위치·길찾기로 연결 | 지역과 장르로 후보를 고르고 선택 이유 설명하기 |
| 기억해 뒀다가 다시 찾기 | 저장한 가게에서 무슨 메뉴가 궁금했는지 잊음 | 메뉴 단위의 먹고 싶은 목록, 목록에서 기록 흐름 진입 | 저장 후 다시 찾아 메뉴와 가게 확인하기 |
| 방금 먹은 메뉴 기록하기 | 리뷰 진입을 찾거나 메뉴를 새로 검색하는 부담 | 주 내비게이션의 기록하기 → 가게 검색 → 메뉴 선택, 별점·본문 우선 | 메뉴가 있는 경우와 없는 경우 각각 기록하기 |
| 전에 먹은 것과 비교하기 | 같은 메뉴의 중복 리뷰·옵션 차이로 혼동 | 한 회원·메뉴 한 리뷰 수정, 주문 옵션 태그 유지 | 기존 리뷰 찾아 옵션과 평가 바꾸기 |
| 없는 가게도 잊지 않고 기록하기 | 등록 검토 동안 내용이 사라짐 | 검색 결과의 가게 요청 진입, 비공개 초안과 상태별 이어쓰기 | 요청 후 초안 복원·승인 후 발행 설명하기 |

원하는 메뉴 보관과 방문 후 리뷰를 분리하는 참고 패턴은 [Google Maps 장소 목록 안내](https://support.google.com/maps/answer/7280933?hl=ko), [리뷰 작성·수정 안내](https://support.google.com/maps/answer/6230175?hl=ko)에서 확인했다(2026-10-17). 이는 다른 제품의 기능 관찰이며 라멘묵자 사용자의 수요·경쟁 우위가 검증됐다는 근거는 아니다. 라멘묵자는 메뉴를 단위로 보관·재평가한다는 제품 결정을 유지한다.

### 3.4 검증할 가설

메뉴 단위 평가와 구체적인 식사 경험이 가게 종합점수만 보는 것보다 선택에 도움이 될 수 있다. 3점의 긍정적 의미와 평가 수 공개가 점수 해석에 도움이 될 수 있다. 이는 사용자 조사나 실험으로 입증된 결과가 아니다.

초기에는 위 과제를 타깃에 해당하는 소수 이용자와 관찰해 첫 클릭·완료 여부·막힌 지점·기록을 반복할 이유를 확인한다. 가게명 찾기, 저장 목록 재방문, 같은 메뉴 수정에 실패하면 IA·문구를 다시 조정한다. 성공률 목표 수치와 분석 도구·추가 개인정보 수집은 아직 확정하지 않는다.

## 4. 핵심 입력 데이터

### 4.1 탐색 조건

검색어, 지역, 메뉴 장르, 정렬, 평가 수 조건을 사용한다. 검색 대상은 가게명·메뉴명·지역이다. 사용자가 위치 기능을 실행하고 권한을 허용한 경우에만 위치를 거리 계산에 이용한다. 거부하면 지역을 직접 고를 수 있어야 한다.

### 4.2 리뷰 입력

| 항목 | 필수 여부 | 기준 |
|---|---|---|
| 메뉴 | 필수 | 해당 가게의 기존 메뉴 선택, 없으면 작성 중 추가. 메뉴 상세 진입 시 해당 메뉴 선택 |
| 전체 별점 | 필수 | 1~5점 정수, 신규 리뷰는 미선택으로 시작 |
| 본문 | 조건부 | 5점이면 특별했던 이유 필수 |
| 국물·면·고명 점수 | 선택 | 해당 없는 항목은 생략 |
| 리뷰 사진 | 조건부 | 기존 메뉴 리뷰는 선택, 새 메뉴 등록 시 필수 사진은 리뷰로 이어짐. 최대 5장 |
| 주문 옵션 | 선택 | `#곱빼기`, `#차슈추가`처럼 직접 추가·삭제하는 태그. 별도 메뉴로 생성하지 않음 |

메뉴 선택과 기본 평가를 먼저 보여주고 선택적인 국물·면·고명 점수는 ‘더 자세히 기록하기’로 펼친다. 진하기·짠맛·면 식감 등 별도 취향 입력과 협찬 여부 입력 필드는 제거한다.

리뷰 작성은 가게 페이지 → 해당 가게의 메뉴 선택(없으면 메뉴 등록) → 리뷰 작성 순서다. 본인이나 다른 사용자가 등록한 기존 메뉴를 보여주고 같은 크기의 `+ 메뉴 추가` 카드 또는 버튼을 옆에 배치한다. 메뉴 추가 화면에서만 “메뉴판에 적힌 전체 이름을 입력해주세요”와 “이미 등록된 메뉴는 추가하지 말고 기존 메뉴를 선택해주세요”를 안내한다.

메뉴 등록에는 메뉴명·가격·장르·사진이 필수다. 공개된 가게에 추가한 메뉴는 관리자 승인 없이 즉시 공개하고 선택 상태로 리뷰 작성을 이어간다. 미등록 가게의 메뉴는 18.1절의 비공개 초안 예외를 따른다. 일반 사용자는 본인이 등록한 메뉴라도 이름을 변경하거나 삭제할 수 없다. 잘못된 정보는 운영자가 수정·정리한다. 특제·곱빼기·추가 토핑은 별도 메뉴로 나누지 않고 리뷰의 주문 옵션으로 표기한다.

메뉴 등록 사진은 별도 홍보 이미지가 아니라 작성 중인 리뷰에 이어지는 사진이다. 같은 파일을 다시 올리지 않도록 리뷰 사진 목록으로 넘긴다. 기존 메뉴 리뷰의 사진은 선택이며, 새 메뉴를 등록할 때만 사진 입력이 필수다. 메뉴 대표 사진은 사진이 있는 공개·유효 리뷰 중 좋아요가 가장 많은 리뷰의 사진을 사용한다. 리뷰가 하나면 그 리뷰의 사진을 사용하고 공개 리뷰 사진이 없으면 회색 임시 이미지를 표시한다. 메뉴만 추가한 뒤 리뷰 작성을 중단하면 미발행 초안 사진을 대표 사진으로 공개하지 않는다.

같은 회원이 같은 가게의 같은 메뉴를 다시 평가하면 새 리뷰를 쌓지 않고 기존 리뷰를 수정한다. 기존 리뷰가 있으면 `내 리뷰 수정`으로 안내하고 별점·본문·사진·선택 평가·주문 옵션을 불러온다. 수정 시 리뷰 수는 늘리지 않고 평균·분포를 갱신하며 작성일과 수정일을 구분해 표시한다.

### 4.3 운영 입력

신고는 대상 리뷰와 사유를 받는다. 가게 등록 요청은 가게명·주소·사용자가 확인한 지도 위치를 받고 메뉴는 해당 가게에 별도로 연결한다. 사용자는 등록 전에 기존 가게를 확인하고, 관리자는 중복·위치·정보를 검토한 뒤 공개한다. 접수만으로 공개 목록에 추가하지 않는다. 메뉴 등록은 가게 등록 요청과 분리하며 관리자 사전 승인을 요구하지 않는다.

## 5. 메뉴 탐색 방식

### 5.1 검색·필터

지역·장르를 조합해 목록을 좁힌다. 검색 조건을 URL에 반영해 새로고침·뒤로 가기·공유 시 복원한다. 공유 URL은 검색 조건을 전달하며 개인 저장 목록을 포함하지 않는다.

### 5.2 정렬·평가 수

명세는 검색 관련도, 평가 많은 순, 평점순, 거리순을 요구한다. 평점순에는 `평가 5개 이상`을 초기 적용한다. 결과가 없으면 ‘평가 수 조건을 해제하고 보기’를 바로 제공하고 선택 시 해당 조건만 해제한다. 거리순은 위치가 있을 때만 제공한다.

검색 관련도는 메뉴명·가게명·지역·태그를 기준으로 계산한다. 여러 단어는 필드를 나누어 모두 일치해야 하며 메뉴명 일치를 우선한다.

### 5.3 목록·지도

Google Maps에는 사용자 등록 요청을 검토해 공개한 가게당 하나의 핀을 표시하고 해당 가게의 메뉴로 연결한다. PC는 목록·지도 병렬, 모바일은 목록·지도 전환을 제공한다. 지도에서 검색되는 가게를 서비스 DB에 자동 등록하지 않는다. 주소 검색·좌표 변환 등 추가 Google API의 사용 여부는 별도 검토한다. 내부 지도 API 키·결제·사용량 제한을 설정해야 하며 지도 연결 실패 시 목록 탐색을 계속 제공한다.

## 6. 별점과 세부 평가

| 점수 | 명세의 설명 |
|---|---|
| 1 | 크게 아쉬웠어요 |
| 2 | 아쉬운 부분이 있었어요 |
| 3 | 맛있게 먹었어요. 좋은 라멘입니다 |
| 4 | 멀리서 찾아가서라도 다시 먹고 싶어요 |
| 5 | 지금까지 먹은 라멘 중 손에 꼽는, 내 인생의 한 그릇입니다 |

5점에는 이유를 받되 주간·월간 횟수 제한을 두지 않는다. 축하 효과나 보상으로 높은 점수를 유도하지 않는다. 국물·면·고명의 선택 점수는 전체 별점에 자동 합산하지 않는다. 별도 취향 입력은 제공하지 않는다.

## 7. 서비스가 제공하는 정보

### 7.1 메뉴 중심 비교

메뉴 사진과 이름을 먼저 보고 가게·지역, 평균·평가 수, 태그, 가격과 저장 기능으로 이어진다. 가게 이름은 기본 UI 폰트를 사용하고 밑줄 없이 상세 링크로 연결한다.

### 7.2 평가의 근거

평균만 보여주지 않고 평가 수와 분포, 리뷰 본문을 함께 확인할 수 있게 한다. 세부 항목에는 응답 수를 표시한다. 리뷰가 없으면 점수 대신 평가 없음 상태를 안내한다.

### 7.3 실제 정보와 체험 정보

실제 서비스에서는 메뉴·가격·판매 상태와 가게 정보의 정확성을 관리한다. 초기 운영자는 직접 라멘집을 방문하고 서비스를 사용하며 실제 가게·메뉴·리뷰를 확보한다. 구체적인 시작 지역은 별도 선택하며 방문 기록·리뷰를 가상 데이터로 채우지 않는다. 가상의 위치를 실제 영업 장소나 길찾기로 표시하지 않는다.

|---|---|

| 메뉴 상세 | 메뉴 특성, 전체·세부 평가, 리뷰, 작성 진입 |
| 가게 상세 | 가게 정보와 판매 중·판매 종료 메뉴 |
| 저장 목록 | 나중에 다시 찾을 메뉴 |
| 내 기록 | 작성한 리뷰와 자신의 별점 분포 |

리뷰 수정·삭제 결과는 목록·상세·집계에 반영한다. 화면의 점수나 문구로 검증되지 않은 객관적 우수성·방문 만족을 보장하지 않는다.

## 9. 평가 집계와 신뢰 기준

- 사용자 한 명은 메뉴 하나에 유효한 리뷰 하나를 갖고 재평가 시 수정한다.
- 메뉴 평균은 공개된 유효 리뷰의 전체 별점으로 계산한다.
- 삭제·숨김 리뷰를 제외하고, 원래 값으로 계산한 뒤 소수 첫째 자리로 표시한다.
- 평가 없음은 0.0으로 표시하지 않는다. 평가 5개 미만이면 `평가가 적어요`를 안내한다.
- 국물·면·고명은 각 응답만 평균 내고 전체 별점을 자동 계산하는 재료로 사용하지 않는다.
- 비공개 사용자 가중치나 임의 점수 보정을 적용하지 않는다.
- 가게 종합점수는 판매 중인 메뉴의 공개 리뷰를 합산한다. 메뉴 평균의 단순 평균을 사용하지 않는다.
- 가게 점수에는 `판매 중인 메뉴 종합`과 계산 범위를 표시하고 메뉴별 평가를 우선한다.

## 10. 데이터 처리와 운영 원칙

### 10.1 애플리케이션의 역할

입력값 검증, 저장·수정·삭제, 평균·분포 계산, 사진 처리, 검색 조건 복원을 수행한다. 현재 개인화 추천이나 AI 호출은 제품 필수 기능이 아니다.

### 10.2 관리자의 역할

정식 운영에서는 사용자가 직접 접수한 가게 등록 요청의 중복·주소·지도 위치와 정보 근거를 검토한 뒤 공개한다. 메뉴는 이메일 인증을 마친 회원이 공개된 가게에 직접 추가하며 관리자 승인 없이 즉시 공개한다. 검토·보완 결과를 안내하고 신고를 처리한다. 신고만으로 리뷰를 자동 삭제하지 않는다. 가격 변경으로 과거 리뷰를 삭제하지 않고 메뉴 구성이 크게 바뀌어 별도 메뉴로 추가하는 경우에도 사전 승인 절차를 두지 않는다. 기존 메뉴의 중복·정보 정리는 공개 후 관리하며 과거 리뷰를 임의로 합치지 않는다.

### 10.3 권한과 개인정보

열람은 비회원도 가능하고 리뷰 작성·저장·신고·등록 요청에는 이메일 인증을 마친 계정의 로그인이 필요하다. 메뉴 추가도 같은 인증 기준을 적용한다. 이메일·비밀번호 가입, 인증 메일 재발송, 비밀번호 재설정과 로그인 복귀를 제공한다. 비밀번호 저장·검증은 Supabase Auth에 맡기고 앱 DB나 로그에 보관하지 않는다. 운영용 메일 발송과 남용 방지를 설정한다. 서버에서 사용자·관리자 권한과 리뷰 소유권을 검증해야 한다. 

사진의 불필요한 메타데이터를 제거하고 위치 이용 범위를 제한한다. Google Maps 연결 시 지도·외부 길찾기·추가 API 요청에 포함되는 좌표와 접속 정보의 전송 범위를 확인하고 정책에 반영해야 한다. 체험 저장소와 외부 이미지·폰트 접속 안내는 이용 정책에 공개한다. 정식 보유기간·운영자 연락처·외부 처리 조건은 운영 환경을 정한 뒤 정책 문서에 반영해야 한다.

## 11. 공통 데이터 관계

```text
가게 1 ── N 메뉴 1 ── N 리뷰 ── 사용자
             │           │
             └── 저장    └── 신고
                사용자

사용자 가게 등록 요청 ── 중복·위치 검토 ── 승인·공개
인증 회원의 공개 가게 메뉴 추가 ── 즉시 공개 (관리자 승인 없음)
미등록 가게 요청 ── 비공개 메뉴·리뷰 초안 ── 가게 승인 후 작성자 발행
Google Maps ── 승인된 가게 표시·길찾기 (자동 등록 없음)
```

| 객체 | 핵심 정보와 관계 |
|---|---|
| 가게 | 이름·지역·주소·위치, 여러 메뉴 보유 |
| 메뉴 | 소속 가게·이름·가격·태그·사진·판매 상태 |
| 리뷰 | 사용자·메뉴·별점·본문·세부 평가·주문 옵션·사진·좋아요 |
| 저장 | 사용자와 메뉴 연결 |
| 신고 | 리뷰와 신고 사유 연결 |
| 등록 요청 | 사용자 입력 가게명·주소·지도 위치·추가 정보, 검토 결과와 공개 여부 |

이 표는 개념 관계이며 새로운 DB 스키마나 API 계약을 확정하지 않는다. 검색·분류 태그는 메뉴에 먼저 연결하고 가게에는 판매 메뉴의 분류 태그를 모아 보여준다. 주문 옵션 태그는 해당 리뷰에만 연결하고 메뉴 분류·필터에 자동 추가하지 않는다.

## 12. 사용자 니즈 중심 정보 구조 (IA)

### 12.1 설계 기준

기존 페이지·라우트 목록을 출발점으로 삼지 않는다. 3절의 타깃이 수행할 세 가지 일인 **먹을 라멘 찾기 / 먹고 싶은 메뉴 다시 찾기 / 먹은 라멘 기록하기**에서 상위 구조를 정하고, 반복 경험은 내 기록으로 묶는다. 아래는 목표 IA다. URL과 기존 코드의 대응·실행 결과는 명세와 배포 문서가 맡는다.

- 라멘 찾기: 비회원도 지역·장르·육수·메뉴명으로 비교한다. 별점 가이드보다 음식 선택에 필요한 정보를 먼저 보여준다.
- 기록하기: 탐색과 독립된 항상 보이는 진입이다. 먹은 가게를 찾아 메뉴를 고르고 실제 쓰기 직전에 인증한다.
- 먹고 싶은: 나중에 먹을 메뉴를 다시 보고 가게 위치 확인·기록으로 이어간다. 작성했다고 자동으로 저장 해제하지 않는다.
- 내 기록: 이전 리뷰와 이어 쓸 비공개 초안을 먼저, 통계·닉네임·탈퇴 같은 계정 관리는 뒤에 둔다.
- 별점 안내·정책·운영 기능은 필요한 맥락과 보조 영역에 둔다. 화면 크기가 달라도 네 가지 목적은 유지한다.

### 12.2 전체 IA

```text
라멘묵자
├─ 홈: 오늘의 목적 선택
│  ├─ 먹을 라멘 찾기 → 지역·메뉴 검색 / 내 근처 / 장르·육수
│  ├─ 먹은 라멘 기록하기 → 가게 찾기
│  └─ 등록된 메뉴 살펴보기 (추천·랭킹으로 포장하지 않음)
├─ 라멘 찾기
│  ├─ 검색 조건 / 결과 목록 ↔ 지도 / 조건 완화·빈 결과 안내
│  └─ 메뉴 상세: 메뉴·가격·장르·평가 수 → 리뷰 근거 → 저장·가게 정보
│     └─ 가게 상세: 위치·길찾기 / 메뉴 비교·선택
├─ 기록하기
│  ├─ 가게 이름·지역 검색 → 가게 선택 → 메뉴 선택
│  │  ├─ 기존 메뉴 → 신규 리뷰 / 내 리뷰 수정
│  │  └─ 메뉴 없음 → 메뉴 등록·사진 이어받기 → 리뷰
│  └─ 가게 없음 → 가게 등록 요청 → 비공개 초안
├─ 먹고 싶은
│  └─ 저장한 메뉴 → 메뉴 정보·가게 확인 / 먹었어요·기록하기 / 저장 취소
├─ 내 기록
│  ├─ 이어서 기록하기: 초안·가게 요청 상태·발행
│  ├─ 내가 먹은 메뉴: 리뷰·수정·삭제
│  ├─ 나의 별점 분포
│  └─ 계정 관리: 닉네임 / 로그아웃 / 탈퇴
└─ 보조·운영
   ├─ 계정 진입: 로그인 / 가입 / 이메일 확인·재발송 / 비밀번호 복구
   ├─ 맥락 도움말: 별점 기준 / 사진 확대 / 신고 / 필터
   ├─ 정책: 약관 / 개인정보 / 리뷰 운영정책
   └─ 관리자: 가게 요청·정보 / 신고 / 보존 자료 개인정보 점검
```

### 12.3 니즈별 화면의 정보 우선순위

| 영역 | 먼저 필요한 정보·행동 | 뒤에 둘 정보 | 완료 기준 |
|---|---|---|---|
| 홈 | 전체 폭 검색, 찾기·기록하기 진입, 지역·장르·육수 | 서비스 설명·별점 철학 | 목적에 맞는 첫 행동 선택 |
| 탐색 | 메뉴 사진·이름·가격·가게/지역·장르·평가 수 | 상세 세부 점수·긴 리뷰 | 후보의 메뉴와 가게 구분 |
| 가게 찾기 | 가게 이름·지역 검색, 동명 가게의 주소, 메뉴 선택 | 종합 점수·다른 사람의 긴 리뷰 | 먹은 가게를 정확히 선택 |
| 가게·메뉴 선택 | 먹은 메뉴 카드와 같은 크기의 메뉴 추가 | 가게 종합 평가 | 메뉴 중복 없이 리뷰 대상 확정 |
| 리뷰 | 대상 확인·별점·본문, 주문 옵션·사진 | 선택 세부 평가 | 검증 후 저장·재평가 결과 확인 |
| 먹고 싶은 | 저장한 메뉴·가게·가격·기록 진입 | 부가 설명 | 후보를 다시 찾거나 기록 시작 |
| 내 기록 | 이어 쓸 초안·요청 상태, 내 리뷰 | 별점 통계·계정 관리 | 이전 경험과 미완료 작업 재개 |

기록하기의 가게 검색과 공개 정보 확인은 비회원에게도 열고 저장·메뉴 추가·리뷰·초안·좋아요·신고·요청 제출 시 이메일 인증을 요구한다. 개인 목록·초안은 본인만, 관리는 관리자만 접근한다. 가입을 탐색의 전제 조건으로 두지 않는다.

### 12.4 공통 탐색·도움말·빈 상태

- PC 주 탐색은 라멘 찾기·기록하기·먹고 싶은과 내 기록, 모바일 하단은 같은 네 항목이다. 로고는 홈으로 돌아간다.
- 필터·별점 가이드·메뉴 추가·가게 요청·신고는 맥락 안에서 처리한다. 계정 관리는 내 기록에서 별도 펼침 영역으로 접근한다.
- 검색 결과가 없으면 검색어 수정과 조건 완화를 제공한다. 평가 수 조건만 문제이면 그 조건만 해제한다.
- 기록할 가게가 없으면 검색어를 확인하고 가게 등록 요청으로 이어진다. 일부 검색 결과가 있어도 원하는 가게가 없을 수 있으므로 요청 진입을 항상 제공한다.
- 지도·위치 실패 시 수동 지역·목록을 유지한다. 등록되지 않은 장소·사진·영업시간·추천 순위를 만들어내지 않는다.
- 저장·리뷰·초안이 비면 찾기·첫 기록 등 실제 가능한 다음 행동을 보여준다. 오류·세션 만료 시 성공으로 안내하지 않는다.

## 13. 니즈별 유저 플로우

### 13.1 오늘 먹을 메뉴 고르기

```text
홈·라멘 찾기 → 지역/메뉴 검색 또는 내 근처·장르·육수 선택
  → 사진·가격·가게/지역·평가 수 비교 → 메뉴 상세의 리뷰 근거 확인
  ├─ 지금 방문 → 가게 상세·위치 확인 → Google Maps 길찾기
  └─ 나중에 먹기 → 인증 → 메뉴 저장 → 먹고 싶은 목록
```

장르명에 익숙하지 않은 사람에게는 닭 육수·돼지 육수·국물 없는 메뉴처럼 데이터에 있는 분류를 병행한다. 위치 권한은 사용자가 요청할 때만 받고 거부해도 수동 탐색한다. 평점순의 평가 5개 이상 조건으로 결과가 없으면 해당 조건만 해제한다. 영업 중 필터·대기 시간·개인화 추천은 데이터 근거가 없으므로 추가하지 않는다.

### 13.2 방금 먹은 라멘 기록하기

```text
어느 화면에서든 기록하기 → 먹은 가게 이름·지역 검색
  → 가게 이름·주소 확인 → 가게 페이지의 메뉴 선택
  ├─ 기존 메뉴 → 인증 → 내 리뷰 유무 확인 → 신규 작성/기존 수정
  └─ 메뉴 없음 → 인증 → 메뉴명·가격·장르·사진 → 중복 확인
     → 새 메뉴 즉시 공개 → 사진 이어받아 리뷰 작성
  → 별점·본문 + 선택 옵션 태그·사진·세부 평가 → 저장 → 메뉴 상세
```

메뉴 상세나 먹고 싶은 목록의 기록 진입도 같은 가게·메뉴 선택으로 연결한다. 기존 내 리뷰 수정은 바로 편집할 수 있다. 입력은 짧게 유지하며 5점의 이유만 필수 본문 조건으로 받는다. 국물·면·고명은 펼쳐 입력한다. 특제·곱빼기·토핑은 주문 옵션 태그이며 메뉴 이름을 바꾸거나 별도 메뉴로 만들지 않는다.

새 메뉴는 기존 결정대로 즉시 공개하고 사용자가 중단해도 메뉴를 자동 삭제하지 않는다. 그 사진은 리뷰에 이어지지만 공개 리뷰에 포함되기 전에는 대표 사진이 아니다. 기존 메뉴 리뷰 사진은 선택이다. 재평가 시 기존 한 리뷰를 수정해 리뷰 수를 유지하고 평균·분포·대표 사진을 갱신한다. 실패하면 내용을 유지하고 다시 제출하게 하며 중복 제출을 막는다.

### 13.3 저장한 메뉴를 다시 찾고 기록하기

```text
먹고 싶은 → 로그인 → 저장한 메뉴·가게 확인
  ├─ 방문 전 → 메뉴 상세 → 가게 위치·길찾기
  ├─ 이미 먹음 → 먹었어요·기록하기 → 가게의 해당 메뉴 선택 → 리뷰
  └─ 관심 없음 → 저장 취소 → 목록 갱신
```

리뷰 작성과 저장은 다른 의도이므로 작성 후 자동 저장 해제를 하지 않는다. 판매 종료 메뉴는 상태를 표시하고 상세·기존 기록 확인 경로를 유지한다. 공개 가게의 메뉴 선택에서는 판매 중 메뉴를 우선한다.

### 13.4 가게가 없을 때 기록 보존하기

```text
기록하기 → 가게 검색·주소 확인 → 원하는 가게 없음
  → 인증 → 가게명·지역·주소·지도 위치 제출 → 비공개 메뉴·리뷰 초안
  → 내 기록의 이어서 기록하기
     ├─ 검토 중 → 계속 작성·저장
     ├─ 반려 → 사유 확인·초안 보존
     └─ 신규 승인/기존 가게 연결 → 작성자가 내용·기존 메뉴 확인
        ├─ 기존 내 리뷰 없음 → 필수 정보 확인 → 직접 발행
        └─ 기존 내 리뷰 있음 → 기존 리뷰·초안 비교 → 필요한 내용 직접 수정
```

가게 승인은 초안의 자동 공개가 아니다. 초안은 지도·공개 목록·평점·대표 사진에서 제외하고 기존 리뷰를 자동 덮어쓰지 않는다. 요청 상태는 내 기록에서 확인하며 알림 채널·초안 보관기간·반려 후 상세 운영 절차는 미정으로 유지한다.

### 13.5 이전 경험 재확인·계정 관리

내 기록 → 이어 쓸 초안 또는 내가 먹은 메뉴 → 기존 리뷰 확인·수정·삭제. 통계와 계정 관리는 기록 확인을 방해하지 않는 보조 영역으로 둔다. 닉네임은 자동 생성값을 수정하고 본인의 공개 작성자명에 반영한다.

탈퇴는 계정 관리 → 삭제/보존 대상 안내 → 공개 리뷰·사진 처리 선택 → 비밀번호·최종 확인 → 서버 처리 → 성공 시 홈 순서다. 개인 저장·초안·불필요 계정정보는 삭제하고 공용 메뉴는 유지한다. 보존 리뷰·사진은 비공개·식별정보 분리 후 운영자 개인정보 점검을 통과한 경우에만 탈퇴한 회원으로 다시 공개한다. 실패를 완료로 표시하지 않으며 보관기간·문의 창구는 별도 확정한다.

### 13.6 인증과 신뢰·운영의 보조 흐름

| 흐름 | 원칙·분기 |
|---|---|
| 로그인 | 읽기 전에 요구하지 않음. 활동 직전 내부 복귀 경로를 전달하고 완료 후 원래 맥락으로 복귀. 이전 쓰기 클릭은 자동 실행하지 않음 |
| 가입·인증 | 이메일·비밀번호·자동 생성 후 수정 가능한 닉네임·약관/연령 확인 → 인증 메일 → 확인 버튼. 맥락이 없거나 다른 기기라면 내 기록에서 다시 시작 가능 |
| 비밀번호 복구 | 메일 요청 → 유효한 복구 확인 → 새 비밀번호 설정. 만료·실패 시 재요청 안내 |
| 좋아요 | 인증 회원이 타인 공개 리뷰에 한 번 추가/취소. 동률 대표 사진은 먼저 작성된 리뷰의 첫 사진 |
| 신고 | 인증 → 사유 → 접수 결과. 신고만으로 자동 삭제하지 않음 |
| 가게 요청 검토 | 관리자 중복·위치 확인 → 신규 승인/기존 가게 연결/사유와 함께 반려. 초안 발행은 작성자가 선택 |
| 보존·메뉴 관리 | 운영자 개인정보·권리 점검, 메뉴 정정. 중복 리뷰를 임의 통합하지 않음 |

### 13.7 검토 기준과 문서 역할

상위 IA는 사용자 목적에서 도출했고 경로는 명세에서 매핑한다. 흐름별 첫 행동·대상 선택·인증 지점·완료·실패·재개를 확인한다. 기존의 이메일 인증, 수동 가게 요청, 공개 메뉴 즉시 등록, 메뉴당 한 리뷰, 좋아요·사진·탈퇴 원칙은 변경하지 않았다. 미정인 알림·보관기간·초기 지역·중복 통합 정책을 새 기능으로 확정하지 않는다. 목표와 실제 구현의 차이는 배포 문서에만 기록하며 목표 IA를 현재 구현에 맞춰 축소하지 않는다.

## 15. MVP 범위와 완료 판단

초기 범위는 메뉴 탐색·가게 상세·가입과 닉네임·가게 등록 요청과 비공개 초안·메뉴 추가·리뷰 작성/수정·주문 옵션·리뷰 좋아요·좋아요 기반 대표 사진·저장·탈퇴·운영 관리다. 취향 입력과 협찬 여부 입력은 범위에서 제외한다. 리뷰 작성의 시작은 가게 페이지로 통일한다.

초기 데이터는 운영자의 실제 방문과 직접 사용으로 확보한다. 구체적인 지역은 아직 정하지 않았다. 명세 14.2절을 완료 조건으로 삼으며 구현 상태와 검증 결과는 배포 문서에서 관리한다.

## 16. 이후 검토와 제품 가설 검증

개인화 추천, 방문 기록, 영수증 인증, 커뮤니티, 리뷰어 등급, 유료 기능·광고 상품은 후속 검토 항목이다. 현재 구현 일정이나 출시 약속으로 정하지 않는다.

제품 검증 시 사용자가 메뉴를 고를 수 있는지, 점수와 평가 수를 함께 이해하는지, 3점·5점의 의미를 이해하는지, 리뷰를 무리 없이 남기는지를 확인하는 것을 제안한다. 목표 전환율·사용자 수·매출 수치는 아직 정하지 않았다. 분석 도구 도입이나 추가 수집은 별도 결정 사항이다.

## 17. 기술·데이터 품질 원칙

- 현재 구조와 공개 API를 보존하고 필요한 최소 변경을 한다.
- 인증·소유권·관리자 권한·입력 검증은 정식 운영 서버에서 처리한다.
- 저장 실패 시 작성 내용을 보존하고 중복 제출을 막는다.
- 외부 장소 데이터와 자체 메뉴·리뷰를 구분하고 사용 조건·출처를 확인한다.
- 위치가 없으면 거리를 임의로 만들지 않는다.
- 외부 사진과 가상 리뷰를 실데이터로 표시하지 않는다.
- 비밀 키·인증 정보는 클라이언트나 문서에 포함하지 않는다.
- 실제 실행한 검증과 확인하지 않은 범위를 구분해 보고한다.

## 18. 확정 정책과 추가 결정

### 18.1 미등록 가게 리뷰 흐름 — 확정

가게 검색 → 없으면 등록 요청 → 메뉴·리뷰 비공개 초안 작성 → 가게 승인 후 작성자가 초안으로 돌아와 발행한다. 가게 승인만으로 메뉴·리뷰를 자동 발행하지 않는다. 승인 전 초안 메뉴·리뷰·사진은 작성자와 검토 권한이 있는 운영자만 접근하며 공개 목록·지도·점수·대표 사진에서 제외한다. 중복 가게로 연결하거나 반려되는 경우 내용을 보존하고 다음 행동을 안내한다. 공개된 가게의 메뉴 추가는 기존처럼 관리자 사전 승인 없이 즉시 공개한다.

[Yelp 가게 추가 안내](https://www.yelp-support.com/article/How-do-I-add-a-business-to-Yelp?l=en_US)는 기존 가게 확인과 신규 가게 검토 후 검색 공개를 설명한다. [Yelp 리뷰 작성 안내](https://www.yelp-support.com/article/How-do-I-write-a-review?l=en_US)는 가게가 없으면 먼저 추가하도록 안내한다. 비공개 초안 연결은 이 사례를 바탕으로 라멘묵자에서 채택한 설계이며 Yelp 기능을 그대로 설명한 것이 아니다. 조사일: 2026-10-17.

### 18.2 탈퇴와 콘텐츠 — 확정

탈퇴 시 개인 저장 목록과 불필요한 계정정보를 삭제하고 사용자가 추가한 공용 메뉴는 유지한다. 공개 리뷰·사진은 탈퇴 전에 삭제 여부를 선택할 수 있게 하고, 보존을 선택한 자료는 작성자 식별정보를 분리하며 본문·사진 등의 개인정보를 점검한 후 보존 여부를 결정한다. 닉네임만 바꾸는 처리를 익명화 완료로 간주하지 않는다. 모든 자료를 무기한 보존하는 정책은 적용하지 않는다. 보관기간·삭제 요청 창구·콘텐츠 이용 범위의 상세 운영 기준은 별도로 정한다.

[개인정보 보호법 제21조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0021&lsiSeq=283839&urlMode=lsScJoRltInfoR)는 불필요해진 개인정보의 파기 원칙을 규정한다. 모든 콘텐츠의 보존 가능 여부를 이 조항 하나로 단정하지 않는다. 확인일: 2026-10-17.

### 18.3 남은 결정

- 인증 회원은 본인 리뷰를 제외한 리뷰에 한 번 좋아요를 누르거나 취소할 수 있다. 대표 사진은 좋아요 수가 같으면 먼저 작성된 리뷰를 우선하고, 그 리뷰의 첫 사진을 사용한다. 중복 메뉴 경고는 예방 안내이며 모든 중복을 막는다는 보장은 아니다. 중복 메뉴 통합 시 한 회원의 리뷰가 겹치는 처리 기준도 미정으로 유지한다.
- 닉네임은 현재 구현에서 글자·숫자·공백·밑줄·하이픈 2~20자로 검증하고 중복을 허용한다. 추가 금칙어·변경 횟수 제한은 미정이며 계정 식별에는 닉네임이 아닌 사용자 ID를 사용한다.
- 운영자의 잘못된 메뉴 정보 정정 절차, 가격·장르·사진 변경 권한.
- 미등록 가게 초안의 보관기간·알림 방식·중복 연결/반려 시 상세 후속 절차. 비공개 초안과 승인 후 작성자 발행 원칙은 확정됐다.
- 탈퇴 처리의 보관기간·삭제 요청 창구·개인정보 점검과 삭제 실패 재처리 기준. 개인 저장 목록 삭제·공용 메뉴 유지·공개 콘텐츠 삭제 선택 원칙은 확정됐다.
- Google Cloud 프로젝트·키·결제·추가 주소 검색 API, 운영용 메일 발송, 초기 방문 지역과 가게 검토 절차.
- 협찬 입력 필드는 제거하되 경제적 이해관계가 있는 게시물의 공개·운영정책은 별도 검토한다. 필드 삭제를 표시 의무가 없다는 의미로 사용하지 않는다. [공정위 안내](https://www.ftc.go.kr/DATA/download/www/cts304_file.pdf) 참고. 확인일: 2026-10-17.

### 18.4 문서 역할

기획서는 제품 결정·제안·미정 항목, 명세서는 동작·예외·권한·완료 조건, 디자인 문서는 화면 표현을 담당한다. 과거 구현 상태와 검증 기록은 [배포 문서](DEPLOYMENT.md)에서 관리한다.

## 19. 제품 핵심 문장

> **라멘묵자는 가게보다 메뉴를 중심으로 라멘을 탐색하고, 평가의 근거와 개인 취향을 비교하며, 먹어본 한 그릇의 경험을 남기는 반응형 웹서비스다.**
