## 1. 문서 목적과 결정 원칙

이 문서는 라멘묵자의 시각 정체성과 화면별 디자인 판단 기준을 정리한다. 기능·데이터·집계 규칙은 [제품 명세](ramenmukja-spec.md)를 따르며, 서비스의 목적과 범위는 [서비스 기획서](PRODUCT_PLAN.md)에 정리한다.

- 최신 사용자 지시를 우선하며, 나머지는 제품 명세를 기준으로 한다.
- 참고 문서인 STEPSYNC의 `DESIGN_IDENTITY.md`에서는 문서 구성, 장·절 구분, 표와 예시 형식만 차용했다. 해당 제품의 브랜드, 컬러, 문구, 디자인 개념과 의사결정 규칙은 가져오지 않는다.
- 아래는 화면 표현 기준이다. 실제 구현 상태·검증 결과는 배포 문서에서 별도로 관리한다.
- 새로운 브랜드 문구는 별도 승인 전까지 내부 설명으로 사용한다.
- 참고 사이트의 표현 방식은 검토할 수 있지만 라멘묵자의 팔레트와 메뉴 중심 원칙을 대체하지 않는다.

## 2. 브랜드

### 2.1 브랜드명

**라멘묵자 / RAMENMUKJA**

라멘을 함께 고르고 먹는 친근한 말투를 사용한다. 가게 순위를 과시하기보다 먹을 메뉴와 개인의 경험을 찾게 한다.

### 2.2 서비스 설명

> **취향으로 찾는 한 그릇**

현재 페이지 제목에 사용하는 서비스 설명이다. 메뉴 탐색과 개인 기록이라는 제품의 두 기능을 연결한다.

### 2.3 내부 디자인 문장

> **음식 사진으로 고르고, 솔직한 취향으로 기록한다.**

이 문장은 디자인 검토를 위한 내부 기준이며 새 공식 태그라인을 확정하는 의미는 아니다.

## 3. 디자인 포지셔닝

### 따뜻한 메뉴판 + 정돈된 미식 수첩

| 성격 | 화면에서의 역할 |
|---|---|
| 라멘 메뉴판 | 음식 사진, 메뉴명, 가격, 장르를 빠르게 비교 |
| 미식 수첩 | 개인의 별점 이유, 국물·면·고명과 주문 옵션을 차분하게 기록 |

두 성격의 면적 비율을 고정하지 않는다. 탐색에서는 메뉴 비교를, 작성 화면에서는 경험 기록을 우선한다.

핵심 키워드: **따뜻함 / 먹음직스러움 / 명료함 / 솔직함 / 메뉴 중심**.

## 4. 전체 시각 원칙

### 4.1 음식이 첫인상을 만든다

크림색 배경과 음식 사진의 색·조명으로 따뜻함을 만든다. 장식보다 사진과 읽기 쉬운 메뉴명이 먼저 보이게 한다.

### 4.2 메뉴가 정보 위계의 중심이다

메뉴 사진 → 메뉴명 → 가게·지역 → 평균·평가 수 → 장르 → 가격·저장 순으로 읽히게 한다. 가게 링크는 메뉴와 구별하되 메뉴명보다 크게 강조하지 않는다.

### 4.3 점수의 근거를 함께 보여준다

평균은 평가 수와 함께 표시한다. 적은 표본을 숨기지 않고, 평가가 없으면 0점으로 표현하지 않는다. 3점도 좋은 평가라는 안내를 유지한다.

### 4.4 반복 장식을 줄인다

섹션 구분선, 일관된 간격, 사진 비율로 구조를 만든다. 모든 정보를 둥근 상자에 넣거나 의미 없는 영문 소제목을 반복하지 않는다. 카드가 필요한 곳에는 명세의 형태 기준을 적용한다.

### 4.5 장르는 작은 단서로 표현한다

그릇 아이콘과 짧은 장르 표기를 사용할 수 있다. 일본어 장식과 붓글씨를 주요 제목·본문에 사용하지 않고 한글 가독성을 우선한다.

## 5. 컬러 시스템

### 5.1 기준 팔레트

제품 명세 3.2절의 값을 그대로 사용한다. HEX 대소문자와 `#FFF` / `#FFFFFF` 표기 차이는 같은 색으로 본다.

| 역할 | 명세 토큰 | CSS 변수 | 기준 HEX |
|---|---|---|---|
| 주요 행동·로고·선택 | `color-primary` | `--primary` | `#C9432B` |
| 전체 배경 | `color-background` | `--bg` | `#FFF8EE` |
| 카드·입력 표면 | `color-surface` | `--surface` | `#FFFFFF` |
| 제목·본문·점수 | `color-text` | `--text` | `#30241F` |
| 주소·날짜·보조 설명 | `color-text-muted` | `--muted` | `#75665D` |
| 작은 배지·장식 | `color-accent` | `--accent` | `#F2B544` |
| 경계선 | `color-border` | `--border` | `#EADFD2` |
| 입력 오류 | `color-error` | `--error` | `#B42318` |

### 5.2 사용 원칙

- 넓은 면적에는 크림색과 흰색을 사용한다.
- 토마토 레드는 주요 버튼, 선택 상태, 로고와 가게 링크처럼 행동 가능한 요소에 사용한다.
- 노른자색은 작은 배지와 장식에 한정한다. 흰색 본문을 올리지 않는다.
- 평점 숫자는 짙은 브라운으로 표시하고 별 모양과 수치를 함께 제공한다.
- 보조 배경은 크림·베이지 계열로 연결한다. 녹색을 별도 브랜드 포인트로 도입하지 않는다.
- 색만으로 링크·선택·오류를 구분하지 않는다. 링크의 위치·굵기, 선택 표시, 설명 텍스트와 포커스를 함께 사용한다.

### 5.3 파생색과 대비

`--primary-dark: #AB3320`은 버튼과 링크의 호버용 파생색이다. 보조 배경·사진 오버레이는 핵심 8개 토큰과 구분한다. 핵심 색을 바꾸려면 명세·이 문서·CSS를 함께 검토한다.

일반 텍스트는 최소 4.5:1 대비를 목표로 검증한다. 팔레트 일치만으로 모든 화면의 접근성 검증이 완료된 것은 아니다.

## 6. 타이포그래피

### 6.1 기본 서체

`Pretendard`를 기본으로 하고 시스템 sans-serif로 대체한다. 가게 이름에도 동일한 폰트를 사용하며 명조체와 밑줄을 적용하지 않는다. 가게 이름의 클릭 기능과 키보드 포커스 표시는 유지한다.

### 6.2 명세의 권장 크기

| 역할 | 권장 기준 |
|---|---|
| 본문 | 16px, 줄 간격 약 1.6 |
| 보조 정보 | 14px |
| 메뉴 제목 | 18–20px |
| 페이지 제목 | 모바일 28px / PC 36px |
| 평점·비교 숫자 | 가능한 경우 `tabular-nums` |

가게 링크는 16px·650 굵기, 메뉴 제목은 20px을 기준으로 한다. 별도 서체 대신 크기·굵기·색상으로 구분한다.

## 7. 레이아웃

### 7.1 탐색의 흐름

```text
검색과 지역·장르 선택
────────────────────
메뉴 사진 / 메뉴명 / 가게 링크
평균과 평가 수 / 태그 / 가격
────────────────────
메뉴 상세와 리뷰
```

### 7.2 PC

기본 콘텐츠 최대 폭은 약 1200px, 목록은 3열로 구성한다. 상세는 주요 정보와 보조 설명을 나눌 수 있다. Google Maps를 목록 옆에 병렬 배치한다. 지도에는 사용자 등록 요청을 검토해 공개한 가게를 표시한다.

### 7.3 모바일

한 열 흐름에 검색·필터·메뉴·상세·작성을 배치한다. 하단 메뉴는 `탐색 / 저장 / 내 기록`이다. 좌우 여백은 최소 16px, 최소 지원 검토 폭은 320px이다.

### 7.4 간격

기준 간격은 `4 / 8 / 12 / 16 / 24 / 32 / 48px`이다. 콘텐츠 간격이 제품의 정보 구조를 드러내게 한다.

## 8. 컴포넌트 형태

### 8.1 카드와 모서리

명세의 권장 모서리는 카드 약 12px, 버튼 약 8px이다. 독립된 메뉴·입력 영역과 섹션 구분을 구별한다. 카드 12px·버튼 8px을 적용한다. 문서의 권장값과 다른 별도 형태 체계를 도입하지 않는다.

### 8.2 버튼과 링크

주요 CTA는 레드 바탕에 명확한 동사로 표시한다. 메뉴 링크, 가게 링크, 저장 버튼은 독립적으로 동작한다. 가게 이름은 밑줄 없이 표시하고 호버 시 더 짙은 레드로 바뀐다. 키보드 포커스는 별도 외곽선으로 표시한다.

텍스트 버튼·링크 옆의 장식용 오른쪽 화살표 `→`는 사용하지 않는다. 검색 제출은 돋보기로 표시한다. 카드·상세의 저장 버튼은 미저장 시 윤곽 책갈피, 저장 시 기본 레드로 채운 책갈피를 사용한다. 상세에는 ‘저장’/‘저장됨’을 함께 표시하고 색 외에 형태·문구·눌림 상태로 구분한다.

### 8.3 아이콘

일관된 선 두께의 단순한 아이콘을 사용한다. 아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다.

## 9. 홈·탐색 화면

검색을 먼저 제공하고 지역·장르별 메뉴로 연결한다. 음식 사진과 메뉴명을 중심으로 비교하게 하며, 매거진 형식의 구분선은 탐색을 돕는 역할에 한정한다.

별점이 높은 메뉴만 좋은 선택처럼 보이게 하지 않는다. 평가 수가 적은 메뉴에는 안내를 제공한다. 평가 수 조건 때문에 결과가 없으면 ‘평가 수 조건을 해제하고 보기’를 바로 보여주고 다른 검색·지역·장르 조건은 유지한다.

---

## 10. 메뉴·가게 상세 화면

메뉴 상세에서는 사진·메뉴명·가게 링크·가격·판매 상태를 확인하고 전체 평가와 세부 항목으로 이어진다. 가게 상세에서는 판매 메뉴와 메뉴별 평가를 우선한다.

가게 종합점수는 `판매 중인 메뉴 종합`으로 명시한다. 판매 종료 메뉴는 별도로 보여준다. 실제 영업시간·위치 정보가 없으면 가상 정보나 준비 상태를 명확히 안내한다.

---

## 11. 리뷰 작성 화면

리뷰 작성은 가게 페이지 → 해당 가게의 메뉴 선택(없으면 메뉴 등록) → 리뷰 작성 순서다. 본인이나 다른 사용자가 등록한 기존 메뉴를 보여주고 같은 크기의 `+ 메뉴 추가` 카드 또는 버튼을 옆에 배치한다. 메뉴 추가 화면에서만 “메뉴판에 적힌 전체 이름을 입력해주세요”와 “이미 등록된 메뉴는 추가하지 말고 기존 메뉴를 선택해주세요”를 안내한다.

메뉴 선택 카드와 메뉴 추가 카드는 같은 폭·높이로 배치한다. 긴 메뉴명은 카드에서 두 줄까지 보여주되 전체 이름은 접근 가능한 링크 이름과 상세 화면에서 확인할 수 있게 한다. 추가 카드에는 더하기 아이콘과 ‘메뉴 추가’를 함께 표시하고 클릭·키보드 조작과 포커스를 제공한다. 메뉴 추가 폼에는 메뉴명·가격·장르·사진의 필수 표시를 제공한다. 특제·곱빼기·추가 토핑은 리뷰의 주문 옵션 태그로 표시한다.

메뉴 선택과 별점·본문을 먼저 보여주고 주문 옵션·사진을 이어 배치한다. 신규 리뷰의 별점은 미선택으로 시작한다. 국물·면·고명은 ‘더 자세히 기록하기’로 펼치며 열림 상태를 보조기기에 알린다. 취향과 협찬 여부 입력은 표시하지 않는다. 메뉴 등록 때 올린 사진은 리뷰 사진 영역에서 그대로 보여주고 재업로드를 요구하지 않는다.

같은 회원이 같은 가게의 같은 메뉴를 다시 평가하면 새 리뷰를 쌓지 않고 기존 리뷰를 수정한다. 기존 리뷰가 있으면 `내 리뷰 수정`으로 안내하고 별점·본문·사진·선택 평가·주문 옵션을 불러온다. 수정 시 리뷰 수는 늘리지 않고 평균·분포를 갱신하며 작성일과 수정일을 구분해 표시한다.

주문 옵션은 입력창과 ‘추가’ 버튼, 확정된 태그 목록으로 구성한다. `#곱빼기`·`#차슈추가`처럼 입력한 이름을 유지하며 Enter 또는 추가로 태그를 만든다. 각 태그에는 접근 가능한 이름을 가진 삭제 버튼을 제공한다. 태그는 좁은 화면에서 줄바꿈하고 공개 리뷰에서는 삭제 버튼 없는 같은 형태로 보여준다. 비공개 초안과 수정 화면에도 동일하게 적용한다. 입력 안내와 전체 300자 초과 오류를 입력창 가까이에 표시한다.

- 5점에는 특별했던 이유를 필수로 받는다.
- 국물·면·고명은 선택 입력이며 ‘더 자세히 기록하기’ 안에 배치한다. 별도 취향 항목은 제공하지 않는다.
- 메뉴 유형에 맞지 않는 항목은 생략한다.
- 저장 실패 시 입력을 보존하고 원인을 안내한다.
- 높은 점수를 유도하는 축하 효과와 보상은 사용하지 않는다.

## 12. 저장·내 기록·정책 문서

저장 화면은 다음에 먹고 싶은 메뉴를 다시 찾는 목록이다. 내 기록은 작성 리뷰와 자신의 별점 분포를 보여준다.

이용약관·개인정보처리방침·리뷰 운영정책은 푸터와 회원가입·로그인 화면에서 접근한다. 로컬 체험 모드에서는 체험 시작 화면에서 접근한다. 문서는 제목·적용일·목차·본문·출처 순으로 읽히게 한다. 미확정 운영 정보를 실제로 제공하는 것처럼 표시하지 않는다.

### 탈퇴 화면의 표현 기준

내 기록 또는 계정 설정에서 탈퇴로 진입한다. 개인 저장 목록·불필요한 계정정보는 삭제되고 공용 메뉴는 유지된다는 점을 구분해 안내한다. 공개 리뷰·사진의 삭제 선택과 보존 시 식별정보 분리·개인정보 점검을 설명하고 최종 선택을 확인한다. 처리 중·완료·실패를 구분하며 보존 콘텐츠의 작성자는 ‘탈퇴한 회원’으로 표시한다. 세부 보관기간은 확정된 운영 정책과 연결하고 임의 수치를 표시하지 않는다.

### 가입·등록·지도 화면의 표현 기준

- 가입 화면은 이메일·비밀번호·닉네임으로 구성한다. 닉네임은 자동 생성한 값과 수정 가능한 입력창을 제공하고 가입 후에도 변경 진입을 제공한다. 실명·전화번호 입력은 추가하지 않는다.
- 이메일 인증 대기·재발송·비밀번호 재설정의 진행과 실패를 구분하고 비밀번호를 화면이나 로그에 노출하지 않는다.
- 가게 등록 요청에는 가게명·주소·지도 위치 확인과 중복 확인을 배치한다. 접수와 승인·공개를 구분한다.
- 공개된 가게의 메뉴 추가에는 승인 대기 상태를 표시하지 않는다. 추가 완료 후 즉시 공개하고 리뷰 작성 화면의 선택 상태를 유지한다.
- 미등록 가게의 메뉴·리뷰에는 ‘비공개 초안’과 ‘가게 검토 중’을 구분해 표시한다. 가게 승인 후에는 ‘이어서 작성하기’와 발행 동작을 제공하고 자동 공개로 오해할 안내를 쓰지 않는다. 중복 연결·반려 상태에는 사유와 초안으로 돌아가는 경로를 제공한다.
- Google Maps는 승인된 가게의 위치를 표시하고 가게·메뉴 화면으로 연결한다. 지도 검색 결과를 자동 등록된 라멘집처럼 표현하지 않는다. Google의 표시·출처 규칙은 연결 시 확인한다.

## 13. 평가 정보 표현

| 상태 | 표현 기준 |
|---|---|
| 평균 | 원래 값으로 계산하고 소수 첫째 자리까지 표시 |
| 평가 수 | 평균과 함께 표시 |
| 평가 5개 미만 | `평가가 적어요` 안내 |
| 평가 없음 | 0.0을 피하고 평가 없음 안내 |
| 별점 분포 | 점수별 수와 비율을 함께 읽을 수 있게 구성 |
| 세부 평가 | 각 항목의 응답 수 표시, 전체 별점과 분리 |

3점은 좋은 식사, 5점은 특별한 한 그릇이라는 의미를 유지한다. 점수만으로 개인 취향이나 방문 가치를 단정하지 않는다.

## 14. 상호작용과 모션

호버·선택·저장 결과는 작은 색상 변화와 짧은 안내로 표시한다. 전환은 명세의 약 150–200ms를 기본으로 한다. 장식용 반복 모션을 추가하지 않는다.

키보드 탐색, 명확한 포커스, 상태 안내, `prefers-reduced-motion`을 유지한다. 터치 목표는 최소 44 × 44px이다. 실제 충족 여부는 배포 문서의 접근성 검증 결과로 확인한다.

## 15. 로고와 이미지

두께감 있고 잘 읽히는 한글 워드마크를 중심으로 작은 그릇·면 요소를 사용할 수 있다. 로고의 포인트는 토마토 레드다.

목록 음식 사진은 1.4:1 비율을 기준으로 일정하게 표시한다. 대표 사진은 명세의 좋아요 기반 공개 리뷰 사진 선정 규칙을 따른다. 공개 리뷰 사진이 없으면 같은 비율의 회색 영역과 ‘사진 없음’ 안내를 표시한다. 메뉴 등록 사진과 리뷰 사진을 중복 입력받지 않는다.

정식 운영에서는 실제 메뉴 사진과 사용 권한·출처를 확인한다. 참고 사진을 실제 메뉴 사진으로 표시하지 않는다.

## 16. 반응형·접근성 기준

| 화면 폭 | 기준 구성 |
|---|---|
| 0–767px | 1열 중심, 하단 내비게이션, 필터 하단 패널 |
| 768–1023px | 2열 목록 |
| 1024px 이상 | 3열 목록, 상세 병렬 배치 가능 |

같은 핵심 기능을 화면 크기에 맞게 재배치한다. 320px에서 가로 넘침이 없어야 하며 고정 하단 메뉴·키보드·안전 영역이 내용을 가리지 않아야 한다. 이 항목은 검증 기준으로, 이번 문서 작성 중 모든 폭을 실측한 결과는 아니다.

## 18. 화면 검토 기준과 문서 연결

- 메뉴 선택과 동일한 크기의 메뉴 추가 카드가 320px·모바일·PC에서 자연스럽게 배치되는가.
- 전체 이름·중복 메뉴 안내가 메뉴 추가 폼에만 나타나는가.
- 닉네임 자동 생성값과 편집 가능 여부가 명확한가.
- 국물·면·고명 펼치기 전에는 기본 평가에 집중할 수 있는가.
- 대표 사진·회색 임시 이미지의 비율이 같고 숨김·삭제 사진이 남지 않는가.
- 결과 없음에서 ‘평가 수 조건을 해제하고 보기’가 바로 보이는가.
